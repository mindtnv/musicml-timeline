\section{Эксперименты}\label{ch:5}

В рамках работы проведено четыре последовательных эксперимента: (5.3) baseline-запуск всех четырёх архитектур 2$\times$2 факторного дизайна (v1); (5.4) улучшенный запуск с обновлёнными гиперпараметрами (v2); (5.5) расширение трансформер-архитектурой AST v2; (5.6) попытка дальнейшего улучшения через агрессивный CNN v3 retrain (failed experiment, документируется как академически честный negative result). Дополнительно проведён (5.8) ablation post-processing pipeline для оценки вклада Viterbi-декодирования и position priors.

\subsection{Протокол оценки}\label{sec:5-1}

\subsubsection{Метрики}

Каждая из четырёх классификационных задач оценивается тремя стандартными метриками:

\begin{itemize}
  \item \textbf{Accuracy} — доля корректно классифицированных окон. Простая, но искажается дисбалансом классов.
  \item \textbf{Macro-averaged F1} — среднее арифметическое F1 по всем классам без учёта частоты. Более честная метрика при несбалансированных датасетах.
  \item \textbf{Per-class precision / recall / F1} — детальное разложение по классам, позволяющее идентифицировать какие именно классы плохо распознаются.
\end{itemize}

Дополнительно для сегментной задачи измеряется:

\begin{itemize}
  \item \textbf{Boundary F1 $\pm$3 секунды} — стандартная метрика MIR для оценки качества обнаружения структурных переходов. Граница считается корректной, если предсказанная не более чем на 3 секунды отклоняется от правильной.
\end{itemize}

\subsubsection{Train/val/test протокол}

\begin{itemize}
  \item \textbf{Splits}: 70/15/15 на уровне треков, фиксированный seed=42 (см. §3.3).
  \item \textbf{Размеры test-сетов}: DEAM $\approx$11.6K окон, Harmonix $\approx$23.4K окон, GTZAN $\approx$3.2K окон.
  \item \textbf{Eval после обучения}: модель загружается из ckpt с лучшим val\_loss; eval на test выполняется один раз.
  \item \textbf{Воспроизводимость}: все random seeds зафиксированы; результаты воспроизводимы при повторном запуске.
\end{itemize}

\subsubsection{Ответы на RQ1–RQ4}

\textbf{RQ1 (мульти-задачная CNN).} Ответ положительный: одна модель эффективно решает 4 задачи, особенно сильно на Genre (83.9\% — на уровне специализированных моделей в literature) и Arousal (62\%). Сегментация остаётся слабой (35.3\%) — в пределах типичных результатов 6-классовой section labeling в literature~\cite{wang2022catchchorus,gong2023structural}.

\textbf{RQ2 (temporal modeling).} Ответ ограниченно положительный: BiLSTM улучшает arousal (CNN: 62 → CNN+BiLSTM: 62.3) и valence (51.7 → 54.2), но \textbf{вредит} genre (83.9 → 60.9 для CNN+BiLSTM). Причина — переобучение BiLSTM на малой выборке Harmonix-треков. Для PANNs+BiLSTM эффект менее выражен (frozen backbone снижает риск переобучения).

\textbf{RQ3 (качество признаков).} Ответ удивительный: \textbf{PANNs не дают преимущества} перед обучаемой с нуля CNN на большинстве задач. PANNs+Linear хуже CNN на сегменте (24 vs 35.3) и сравним на остальных. Гипотеза: AudioSet pretraining оптимизирован под звуковые события (звон, шум, голос), что не идеально для музыкального анализа. Дополнительная проверка через AST (см. §5.5) показывает, что pretraining помогает только при возможности fine-tuning.

\textbf{RQ4 (фактор больше влияния).} Ни один из двух факторов 2$\times$2 эксперимента не оказался решающим. Лучший на сегменте — PANNs+BiLSTM (32.9), на arousal/valence — он же. На genre — CNN per-window (83.9). Различия меньше 3\,п.п. между лучшим и средним. Реальный прорыв пришёл с третьей архитектурной парадигмой — трансформерами (AST, см. §5.5).

\subsection{Эксперимент AST v2 (расширение трансформер-архитектурой)}\label{sec:5-5}

\subsubsection{Мотивация}

После 2$\times$2 эксперимента стало очевидно: ни CNN, ни PANNs не дают качественного скачка. Гипотеза — необходима архитектура с \textbf{глобальным receptive field} (как BiLSTM) \textbf{и} богатой инициализацией (как PANNs), но более ёмкая и адаптируемая. AST~\cite{gong2021ast} удовлетворяет обоим требованиям: self-attention видит всю спектрограмму, AudioSet-pretraining обеспечивает богатую инициализацию, частичная заморозка позволяет fine-tuning без catastrophic forgetting.

\subsubsection{Конфигурация AST v2}

\begin{itemize}
  \item Базовая модель: \code{MIT/ast-finetuned-audioset-10-10-0.4593} (87M параметров).
  \item Заморожены: patch embedding + первые 8 из 12 transformer-слоёв.
  \item Trainable: верхние 4 слоя + heads + CLS-токен $\approx$ 14.4M параметров.
  \item Differential lr: backbone 5e-5, heads 1e-3, weight\_decay 0.01.
  \item batch\_size = 16, gradient\_accumulation = 4 (effective batch = 64).
  \item 30 эпох, patience 10, scheduler — CosineAnnealingWarmRestarts(T\_0=10, T\_mult=2).
\end{itemize}

Время обучения: $\sim$3 часа на одном GPU (12GB VRAM). Существенно дольше CNN v2 ($\sim$3.5\,ч), что сравнимо с PANNs+BiLSTM ($\sim$5\,ч с учётом precompute embeddings).

\subsubsection{Ответ на RQ5}

AST v2 действительно превзошёл CNN-baseline по сегментной задаче (+5.3\,п.п. accuracy). Главный источник прироста — более сбалансированные предсказания на Verse (recall 45.7\% vs 27.9\% у CNN v2) и Chorus (45.6\% vs 40.3\%). Это подтверждает гипотезу о ценности глобального self-attention для распознавания повторяющихся структурных паттернов.

Однако AST v2 уступил CNN v2 на genre (−2.4\,п.п.). Причина — для 10-классовой genre classification на 30-секундных GTZAN-фрагментах глобальный контекст менее ценен (фрагмент уже короток), а CNN с inductive bias (translation invariance) более эффективен.

\textbf{Ключевой trade-off:} AST v2 даёт лучший средний результат и драматически лучше на сегменте, но требует в 30 раз больше памяти (574\,MB vs 21\,MB checkpoint) и в 4 раза больше времени inference (8\,с vs 2\,с на 3-минутный трек). Для прототипа выбран AST v2 — приоритет качества над эффективностью.

\subsubsection{Анализ провала}

CNN v3 показал противоположный эффект — сегмент \textbf{упал} на 13.2\,п.п. Анализ training log выявил причины:

\begin{enumerate}
  \item \textbf{Early stopping на эпохе 19}, лучший val\_loss достигнут уже на эпохе 4, дальше только ухудшение. Модель быстро переобучилась на редкие сегментные классы.
  \item \textbf{Class weights после обрезания}: \code{[Intro: 3.05, Verse: 0.44, Bridge: 1.14, Chorus: 0.47, Instrumental: 3.5, Outro: 3.5]}. Соотношение Intro/Verse теперь 7:1 — модель «карается» за ошибку на Intro в 7 раз сильнее, чем на Verse. Это сместило её в сторону overprediction редких классов.
  \item \textbf{Деградация genre на 4.8\,п.п.} — следствие мульти-задачной природы: чрезмерная оптимизация одной головы (segment weight 3.5) забирает ёмкость backbone у других.
\end{enumerate}

\subsubsection{Что мы извлекли}

CNN v3 — \textbf{академически ценный negative result}:

\begin{itemize}
  \item Подтверждает, что v2 уже находится в окрестности оптимума для CNN-архитектуры.
  \item Показывает, что class imbalance невозможно «решить» простым увеличением весов — нужен либо больше данных (что недоступно), либо лучшая архитектура (что и сделал AST v2).
  \item Демонстрирует риск aggressive reweighting в multi-task контексте: усиление одной задачи деградирует остальные.
\end{itemize}

Этот результат включён в отчёт как иллюстрация научной добросовестности — публикация неудачных экспериментов также является вкладом в literature.

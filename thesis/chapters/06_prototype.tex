\section{Прототип системы}\label{ch:6}

В рамках работы реализован полнофункциональный веб-прототип, демонстрирующий практическое применение разработанной модели. Прототип принимает на вход аудиофайл произвольного формата (MP3, WAV, FLAC, OGG), выполняет полный анализ через AST v2 + post-processing pipeline и отображает результаты в виде синхронизированного дашборда с шестью аналитическими панелями. Архитектура построена по принципу \textbf{трёхзвенного приложения}: Python-сервис ML inference, TypeScript-сервис управления данными, React-фронтенд. Дашборд использует кастомный фреймворк синхронизации на базе React Context + d3-scale, что обеспечивает плавную одновременную анимацию воспроизведения на всех панелях.

\subsection{Архитектура веб-приложения}\label{sec:6-1}

\subsubsection{Трёхзвенная структура}

Прототип состоит из трёх независимых сервисов, соединённых REST-API:

\begin{lstlisting}
+----------------+    HTTP    +-----------------+   HTTP    +-----------------+
|  Frontend      | ---------> |  Backend        | --------> |  ML API         |
|  React + Vite  |            |  Elysia + Bun   |           |  FastAPI        |
|  port 5173     | <--------- |  port 3000      | <-------- |  port 8000      |
+----------------+            +-----------------+           +-----------------+
                                       |
                                       v
                                +--------------+
                                |  uploads/    |
                                |  data/*.json |
                                +--------------+
\end{lstlisting}

\textbf{ML API (Python, FastAPI, port 8000).} Содержит загруженную в память модель AST v2 (574\,МБ checkpoint). Endpoints:

\begin{itemize}
  \item \code{POST /analyze} — принимает audio multipart upload, возвращает JSON timeline с полным анализом (segment, arousal, valence, genre + frame\_predictions).
  \item \code{POST /spectrogram} — возвращает downsampled mel-спектрограмму как 2D-массив для отображения.
  \item \code{GET /health} — health check для мониторинга.
\end{itemize}

\textbf{Backend (TypeScript, Elysia, Bun runtime, port 3000).} Управляет жизненным циклом треков и пользовательскими uploads. Endpoints:

\begin{itemize}
  \item \code{POST /api/tracks} — создаёт новый трек из загружаемого файла.
  \item \code{GET /api/tracks} — список всех треков с метаданными.
  \item \code{GET /api/tracks/:id} — детали конкретного трека (включая timeline).
  \item \code{POST /api/tracks/:id/analyze} — запускает анализ трека через ML API, сохраняет результат.
  \item \code{GET /api/tracks/:id/audio} — отдаёт аудиофайл для воспроизведения в браузере.
  \item \code{GET /api/tracks/:id/spectrogram} — проксирует запрос к ML API + кэширует результат в RAM.
  \item \code{DELETE /api/tracks/:id} — удаляет трек и связанные файлы.
\end{itemize}

Хранение: треки сохраняются как JSON-файлы в \code{web/backend/data/}, аудио — в \code{web/backend/uploads/}. База данных не используется — для прототипа достаточно файловой системы.

\textbf{Frontend (TypeScript, React 19, Vite, port 5173).} Двухстраничное SPA:

\begin{itemize}
  \item \code{/} — список загруженных треков с поиском и сортировкой, форма upload.
  \item \code{/tracks/:id} — дашборд анализа трека (главное представление).
\end{itemize}

\subsubsection{Объединённый запуск (dev-all.ts)}

Для упрощения разработки реализован Bun-скрипт \code{scripts/dev-all.ts}, запускающий все три сервиса параллельно:

\begin{lstlisting}[language=JavaScript]
const services = [
  { name: "ml-api",   cwd: ROOT,             cmd: ["python", "scripts/serve_ml.py", ...] },
  { name: "backend",  cwd: "web/backend",    cmd: ["bun", "run", "dev"] },
  { name: "frontend", cwd: "web/frontend",   cmd: ["bun", "run", "dev"] },
];
for (const svc of services) {
  const p = spawn({ cmd: svc.cmd, cwd: svc.cwd, ... });
  prefixStream(p.stdout, svc.name, svc.color);  // [ml-api] / [backend] / [frontend]
}
\end{lstlisting}

Запуск всего стека одной командой \code{bun run scripts/dev-all.ts} или через preview-конфиг \code{musicml}. Логи с цветными префиксами облегчают debugging.

\subsection{Synchronized music dashboard}\label{sec:6-2}

Главное технологическое решение прототипа — \textbf{синхронизированный дашборд} из шести аналитических панелей, разделяющих общее представление о времени. Курсор воспроизведения (playhead) одновременно движется по всем панелям, hover на любой панели подсвечивает соответствующий момент времени на остальных, клик ставит «закладку» (pinned cursor), сохраняющуюся пока пользователь её не снимет.

\subsubsection{Архитектурный фреймворк синхронизации}

Реализован собственный лёгкий фреймворк на основе React Context + d3-scale. Базовые компоненты:

\textbf{\code{DashboardContext}} — провайдер общего состояния:

\begin{lstlisting}[language=JavaScript]
interface DashboardState {
  duration: number;             // track duration
  playheadTime: number;         // current playback position
  hoverTime: number | null;     // mouse hover (null = outside)
  pinnedTime: number | null;    // pinned cursor
  isPlaying: boolean;
  seek(t: number): void;
  setHoverTime(t: number | null): void;
  setPinnedTime(t: number | null): void;
  togglePlay(): void;
}
\end{lstlisting}

Provider запускает rAF-loop (\code{requestAnimationFrame}), обновляющий \code{playheadTime} 60 раз в секунду в течение воспроизведения. Все панели подписываются через хук \code{useDashboard()}.

\textbf{\code{useTimeScale(containerRef, padding)}} — хук для конвертации time → pixel в каждой панели. Использует \code{scaleLinear} из d3-scale + \code{ResizeObserver} для перерасчёта при изменении размеров контейнера:

\begin{lstlisting}[language=JavaScript]
const ts = useTimeScale(containerRef, paddingLeft, paddingRight);
const pixelX = ts.scale(timeInSeconds);     // time -> pixel
const time = ts.invert(pixelXFromMouse);    // pixel -> time
\end{lstlisting}

\textbf{\code{ChartFrame}} — обёртка-контейнер для каждой панели. Принимает \code{height} и render-prop с измеренным \code{timeScale}:

\begin{lstlisting}[language=JavaScript]
<ChartFrame height={120}>
  {({ timeScale, width, height }) => (
    <MyCustomCanvas timeScale={timeScale} width={width} height={height} />
  )}
</ChartFrame>
\end{lstlisting}

Внутри ChartFrame обрабатываются click (→ \code{seek} + \code{setPinnedTime}), mousemove (→ \code{setHoverTime}), mouseleave (→ \code{setHoverTime(null)}). Поверх вынесён компонент \code{TimeCursor}, рисующий три типа курсоров (см. §6.2.3).

\subsubsection{Шесть аналитических панелей}

\textbf{Панель 1: Структура композиции (\code{StructurePanel}).} Отображает результат сегментации:

\begin{itemize}
  \item Цветная полоска (canvas) с делением на сегменты по времени, метки внутри широких сегментов.
  \item Список всех сегментов справа с временами и confidence (\code{Куплет 0:08 → 0:24, 54\%}).
  \item Клик на сегмент в списке — seek в соответствующее время + pin курсора.
\end{itemize}

\textbf{Панель 2: Эмоциональный анализ (\code{EmotionPanel}).} Совмещает классификацию и регрессию:

\begin{itemize}
  \item Две короткие полоски-таймлайна: arousal (Low/Mid/High) и valence (Dark/Neutral/Bright) с цветовой кодировкой.
  \item Под ними — кривая регрессионных значений arousal\_reg и valence\_reg во времени (canvas), с сеткой по горизонтали.
  \item Легенда: красная линия — Arousal, фиолетовая — Valence.
\end{itemize}

\textbf{Панель 3: Эмоциональная траектория (\code{AVTrajectory}).} 2D-визуализация Russell circumplex:

\begin{itemize}
  \item Квадрат 320$\times$320 с разделением на 4 квадранта (Злое/Радостное/Грустное/Умиротворённое).
  \item Горизонтальная ось — Valence, вертикальная — Arousal.
  \item Серая полупрозрачная линия — траектория за весь трек.
  \item Красный «комет» — последние 20 секунд траектории с градиентом opacity (свежие точки ярче, старые тусклые).
  \item Красная точка со свечением — текущий момент воспроизведения.
  \item Справа — числовые значения Valence и Arousal в текущей точке.
\end{itemize}

Использование классификационных вероятностей вместо регрессии для координат:

\begin{equation}
x_{\text{val}} = 0.5 + 0.5 \cdot \big( P(\text{Bright}) - P(\text{Dark}) \big), \quad
y_{\text{aro}} = 0.5 + 0.5 \cdot \big( P(\text{High}) - P(\text{Low}) \big).
\end{equation}

Регрессионные предсказания смещены к центру (систематический bias модели) — все треки скапливались бы в квадранте «Грустное». Классификационная разность даёт сбалансированное распределение по всему квадранту.

\textbf{Панель 4: Жанр композиции (\code{GenrePanel}).} Многоуровневое представление:

\begin{itemize}
  \item \textbf{Сверху}: топ-3 жанров с прогресс-барами (\code{1. Поп 47\%  2. Рок 23\%  3. Хип-хоп 18\%}). Каждый бар окрашен соответствующим жанровым цветом, ширина — пропорциональна вероятности.
  \item \textbf{Warning при низкой уверенности}: если top-1 $<$ 45\%, показывается жёлтая плашка «Низкая уверенность классификации. Трек вероятно вне 10 классов GTZAN (electronic, ambient, lo-fi и т.п.)».
  \item \textbf{Strip timeline}: цветная полоска dominant genre по времени.
  \item \textbf{Stacked area chart}: полная stacked area всех 10 жанров с d3-shape.stack (toggle через checkboxes легенды).
\end{itemize}

Top-3 + warning — ключевое UX-решение, адресующее out-of-distribution проблему GTZAN (см. §7.3).

\textbf{Панель 5: Мел-спектрограмма (\code{SpectrogramPanel}).} Отображение «входа модели»:

\begin{itemize}
  \item Canvas 128 $\times$ T пикселей с viridis-окраской: тёмно-фиолетовый = тишина, синий = низкая энергия, зелёный = средняя, жёлтый = высокая.
  \item Низкие частоты внизу, высокие сверху.
  \item Применена gamma-коррекция ($\gamma=0.4$) для компенсации сжатого dynamic range log-мел.
  \item Источник данных: endpoint \code{/spectrogram} ML API возвращает downsampled (max 512 frames) JSON-массив; frontend строит ImageData через viridis LUT и отрисовывает на canvas.
\end{itemize}

Эта панель академически ценна — она показывает \textbf{что именно «видит» модель} в качестве входа, превращая black box в интерпретируемое представление.

\textbf{Панель 6: Сводка (\code{SummaryPanel}).} Числовые статистики:

\begin{itemize}
  \item Pie chart распределения времени по типам сегментов (\code{Куплет 35\%, Припев 28\%, Бридж 12\%, ...}).
  \item Доминирующий жанр + confidence.
  \item Темп BPM (из librosa beat tracking).
  \item Тональность (из librosa key estimation).
  \item Средняя энергия (mean over arousal\_probs derived score, см. §6.3).
  \item Среднее настроение (то же для valence\_probs).
  \item Количество структурных переходов.
\end{itemize}

\subsection{Ключевые UX-решения}\label{sec:6-3}

\subsubsection{Top-3 жанров + confidence warning}

Стандартная «правильная» подача жанровой классификации — показать top-1 с процентом. Это создаёт ложное впечатление уверенности модели на любых аудио, включая out-of-distribution (современная электроника, lo-fi, phonk не входят в 10 классов GTZAN).

Реализованное решение:

\begin{enumerate}
  \item \textbf{Показ top-3} — пользователь видит, что модель не уверена и колеблется между несколькими жанрами.
  \item \textbf{Confidence warning} при top-1 $<$ 45\% — явное информирование о низкой уверенности.
  \item \textbf{Подпись к панели} «Классификация в 10 жанров GTZAN-2002. Современные жанры (electronic, indie, lo-fi и др.) сопоставляются с ближайшим» — устанавливает realistic expectations.
\end{enumerate}

Это повышает доверие к системе через \textbf{академическую честность}: лучше показать «не уверен», чем уверенно ошибиться.

\subsubsection{Russell circumplex по классификации, не регрессии}

Изначальная реализация использовала arousal\_reg и valence\_reg как координаты — это привело к тому, что \textbf{все треки оседали в квадранте «Грустное»} (low arousal, low valence). Причина: регрессионные head обучены MSE-loss и систематически смещены к среднему распределения (центр шкалы).

Решение — использовать \textbf{классификационную разность} $P(\text{positive}) - P(\text{negative})$, центрированную в $[0, 1]$. Это даёт сбалансированное распределение по всему квадранту, точно отражающее эмоциональную динамику трека (см. §6.2.2).

\subsection{Endpoint мел-спектрограммы}\label{sec:6-4}

Для отображения панели Mel-Spectrogram в ML API добавлен endpoint \code{POST /spectrogram}:

\begin{lstlisting}[language=Python]
@app.post("/spectrogram")
async def spectrogram(file: UploadFile = File(...)):
    audio, sr = load_audio(audio_path, sr=22050)
    mel = compute_log_mel(audio, sr=sr, n_mels=128, hop_length=512)
    # Downsample T -> max 512 frames for payload size
    if mel.shape[1] > 512:
        idx = (np.arange(512) * mel.shape[1] / 512).astype(int)
        mel = mel[:, idx]
    # Normalize 0..1 for viridis colormap on frontend
    mel_norm = (mel - mel.min()) / (mel.max() - mel.min() + 1e-6)
    return {"mel": np.round(mel_norm, 3).tolist(), "n_mels": 128, ...}
\end{lstlisting}

Backend проксирует запрос с in-memory кэшированием (\code{Map<trackId, spectrogramData>}). На frontend данные отрисовываются на canvas через precomputed viridis LUT (256 entries):

\begin{lstlisting}[language=JavaScript]
// Build viridis LUT once
const lut = new Uint8Array(256 * 3);
const tmpCtx = document.createElement("canvas").getContext("2d");
for (let i = 0; i < 256; i++) {
  tmpCtx.fillStyle = interpolateViridis(i / 255);
  tmpCtx.fillRect(i, 0, 1, 1);
}
const lutData = tmpCtx.getImageData(0, 0, 256, 1).data;
// ... copy RGB into lut

// Render: for each pixel take mel value -> LUT index -> RGB
const pixelValue = Math.pow(melRow[x], 0.4);  // gamma correction
const lutIdx = Math.round(pixelValue * 255);
img.data[idx] = lut[lutIdx * 3];       // R
img.data[idx+1] = lut[lutIdx * 3 + 1]; // G
img.data[idx+2] = lut[lutIdx * 3 + 2]; // B
\end{lstlisting}

Gamma-коррекция ($\gamma=0.4$) брайтит средние значения, делая структуру спектрограммы видимой (без неё большая часть пикселей выглядела чёрной из-за компрессированного dynamic range log-mel).

Альтернативы (рассмотрены и отвергнуты):

\begin{itemize}
  \item \textbf{Redux/Zustand для state} — overkill для двух страниц.
  \item \textbf{TailwindCSS} — слишком много шаблонной разметки в classNames.
  \item \textbf{Recharts/Visx} — недостаточная гибкость для синхронизированного playhead через все панели.
  \item \textbf{Node.js backend вместо Bun} — Bun запускается в 4 раза быстрее, удобнее для прототипирования.
\end{itemize}

\textbf{Резюме главы 6.} Реализован полнофункциональный веб-прототип с трёхзвенной архитектурой (ML API + Backend + Frontend). Главное достижение — синхронизированный музыкальный дашборд из шести панелей с общим состоянием времени через кастомный React Context фреймворк. Шесть панелей покрывают все аспекты анализа (структура, эмоции, жанр, 2D-траектория, спектрограмма, статистика). UX-решения учитывают академическую честность (top-3 + warning для OOD), смягчают известные bias модели (классификационные координаты вместо регрессионных) и обеспечивают полировку production-уровня (skeletons, empty states, search, muted palette). Прототип служит и демонстратором результатов работы, и инструментом дальнейшего исследования для конечных пользователей.

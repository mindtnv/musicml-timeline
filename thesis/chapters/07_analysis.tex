\chapter{Анализ результатов и ограничения}\label{ch:7}

Глава суммирует ответы на исследовательские вопросы RQ1--RQ5, фиксирует финальную конфигурацию модели, идентифицирует ограничения и сопоставляет результаты с state-of-the-art.

\section{Сводные ответы на исследовательские вопросы}\label{sec:7-1}

\textbf{RQ1 (мульти-задачная CNN): положительный с оговорками.} CNN~v2 конкурентна на трёх из четырёх задач: Genre~83{,}9\,\% (в диапазоне CNN-baseline 75--87\,\%~\cite{choi2017crnn,sigtia2014improved}), Arousal~62{,}0\,\%, Valence~51{,}7\,\% (близко к single-task SOTA на DEAM~\cite{wang2017autotagging,won2020selfattention}), Segment~35{,}3\,\% (в типичном диапазоне 6-классовой section labeling 30--45\,\%~\cite{wang2022catchchorus,gong2023structural}). MTL не привело к катастрофической деградации относительно single-task baseline (ablation~§5.7).

\textbf{RQ2 (temporal modeling~--- BiLSTM): смешанный.} BiLSTM улучшает arousal (+0{,}3) и valence (+2{,}5) для CNN+BiLSTM, но резко вредит genre ($-23$) из-за переобучения на 699~GTZAN-треков. Для PANNs+BiLSTM эффект мягче (frozen backbone). Главный недостаток~--- сокращение числа обучающих примеров ($\sim$500~последовательностей против $\sim$16\,K~окон).

\textbf{RQ3 (качество признаков~--- PANNs vs from-scratch): PANNs не дают преимущества.} PANNs+Linear проигрывает CNN~v2 на 3~из 4~задач (Segment~$-11{,}3$, Arousal~$-0{,}8$, Genre~$-2{,}0$; только Valence~$+2{,}1$). AudioSet-pretraining оптимизирован под звуковые события, не под структурный музыкальный анализ; frozen embeddings не адаптируются. Transfer learning оправдан лишь при возможности fine-tuning (AST, RQ5).

\textbf{RQ4 (главный фактор влияния): ни один из двух факторов не решающий.} В 2$\times$2 максимальная разница между лучшим и средним конфигом~--- 3--5\,п.п. Прорыв пришёл с третьим фактором~--- архитектурным семейством трансформеров (RQ5).

\textbf{RQ5 (AST): положительный с trade-off.} AST~v2 даёт лучший результат на сегменте (40{,}6\,\% vs 35{,}3\,\%, +5{,}3\,п.п.) и лучшее среднее по 4~задачам (58{,}5\,\%) за счёт глобального self-attention для распознавания повторяющихся структурных паттернов. На genre AST уступает CNN~v2 ($-2{,}4$\,п.п.)~--- для 30-секундных GTZAN-фрагментов CNN inductive bias эффективнее. Trade-off: 30$\times$ памяти (574\,МБ vs 21\,МБ) и 4$\times$ времени inference (8\,с vs 2\,с).

\section{Ограничения текущего подхода}\label{sec:7-3}

\begin{itemize}
  \item \textbf{OOD на современной музыке.} Жанровая голова обучена на GTZAN-2002 (10~устаревших классов); electronic, ambient, lo-fi, phonk, hyperpop не представлены. Поведение: электроника и ambient $\to$ \code{classical} (fallback для не-ударного инструментального), lo-fi $\to$ \code{hiphop} по drum-паттернам. Mitigation в прототипе: top-3~+~confidence warning~+~подпись к панели. Долгосрочно: дообучение на FMA (161 субжанр) или MagnaTagATune (188 multi-label).
  \item \textbf{Нижний предел сегментной задачи.} Section labeling 40{,}6\,\% (AST) ограничен класс-имбалансом (Verse+Chorus~=~60\,\% окон Harmonix), annotator disagreement 25\,\%~\cite{smith2011salami}, acoustic ambiguity (Verse/Pre-chorus, Intro/Outro) и domain shift (Harmonix~--- преимущественно поп 2000-х). Post-processing повышает Boundary~F1 с 0{,}31 до 0{,}45 (+14\,п.п.), но фундаментальный потолок~$\approx$50\,\% без новых данных; долгосрочно~--- SALAMI (classical/jazz/world) или synthetic augmentation.
  \item \textbf{Размер и латентность.} Checkpoint~574\,МБ, inference~8\,с на 3-минутный трек~--- непригодно для mobile, real-time и batch ($\sim$2{,}2\,ч на 1000~треков). Mitigation: переключение на CNN~v2 (21\,МБ, 2\,с) через \code{serve\_ml.py --ckpt checkpoints/cnn\_v2/best.pt} ($-5{,}3$\,п.п. сегмент, $+2{,}4$\,п.п. жанр). Долгосрочно~--- knowledge distillation AST$\to$CNN и INT8-квантизация.
  \item \textbf{Single-label genre.} Модель предсказывает один жанр, хотя реальные треки часто мульти-жанровые (pop-rock, electronic-jazz). Mitigation: top-3 в UI. Долгосрочно~--- multi-label датасет + BCE + threshold-based prediction.
  \item \textbf{Длинные треки.} AST обрабатывает окна по 10\,с с шагом 1\,с; для треков~$>$8\,мин память для per-frame predictions влияет на UI. Протестировано до 5~минут. Долгосрочно~--- streaming inference со скользящим окном или иерархический анализ.
\end{itemize}

\section{Научная новизна и практическая значимость}\label{sec:7-5}

\textbf{Научная новизна.} (1)~Систематическое сравнение пяти архитектур для мульти-задачного MIR на едином датасете~--- отсутствует в literature (обычно 2--3). (2)~Документированный negative result CNN~v3~--- академически честное сообщение о провале aggressive reweighting. (3)~Композитный post-processing pipeline (Viterbi + position priors + iterative min-duration merge) с количественной оценкой вклада каждого компонента. (4)~OOD honest UX~--- top-3 + confidence warning как pattern для academic-honest классификации.

\textbf{Практическая значимость.} Open-source прототип для исследований и обучения; воспроизводимый pipeline по конфигам в \code{configs/}; демонстрационная система для musicians/researchers/music-apps developers; базис для real-time inference, mobile deployment и новых датасетов.

\textbf{Резюме главы~7.} Ответы на RQ1--RQ5 подтверждают применимость мульти-задачного DL к MIR с trade-off между задачами. Финальная модель~--- AST~v2 + Viterbi post-processing, среднее качество 58{,}5\,\%, segment 40{,}6\,\%. Идентифицированы 5~групп ограничений с mitigation в текущей реализации. Разрыв со SOTA 5--8\,п.п.~--- приемлемый для первой комплексной мульти-задачной реализации с production-prototype.

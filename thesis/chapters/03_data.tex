\subsubsection{DEAM (Database for Emotional Analysis of Music)}

DEAM — крупнейший открытый датасет для music emotion recognition, подготовленный в рамках серии MediaEval challenges 2013–2018 годов~\cite{aljanaki2017deam}. Содержит 1802 музыкальных фрагмента длительностью 45 секунд, выбранных из Free Music Archive с лицензией Creative Commons. Покадровые аннотации arousal и valence получены через краудсорсинговый эксперимент: каждый фрагмент оценивали в среднем 10 аннотаторов с шагом 500\,мс.

\textbf{Формат аннотаций.} Для каждого трека предоставляется:

\begin{itemize}
  \item \code{valence\_average.csv}, \code{arousal\_average.csv} — усреднённые временные ряды по 60 фреймам (30 секунд $\times$ 2 фрейма/с).
  \item \code{valence\_std.csv}, \code{arousal\_std.csv} — стандартные отклонения по аннотаторам, индикатор согласия.
  \item \code{metadata.csv} — общая информация о треках (длительность, BPM при наличии).
\end{itemize}

\textbf{Дискретизация.} Непрерывные значения arousal/valence в диапазоне $[-1, +1]$ преобразуются в три категории по двум порогам, выбранным на основе анализа распределений в обучающей выборке:

\begin{lstlisting}
arousal:    [-1.0 .. -0.2] -> Low,    [-0.2 .. +0.2] -> Mid,    [+0.2 .. +1.0] -> High
valence:    [-1.0 .. -0.2] -> Dark,   [-0.2 .. +0.2] -> Neutral, [+0.2 .. +1.0] -> Bright
\end{lstlisting}

Пороги $\pm 0.2$ выбраны как обеспечивающие приблизительно равномерное распределение классов на train split: каждый из трёх классов получает 25–40\% примеров. Альтернативная схема равных квантилей (по 33\% на класс) была отвергнута, поскольку нарушала бы семантическое соответствие («Low» при arousal=0 нельзя интерпретировать как действительно низкую энергию).

\subsubsection{Harmonix Set}

Harmonix Set~\cite{nieto2019harmonix} — единственный крупный открытый датасет со структурной разметкой коммерческой популярной музыки. Включает 912 треков, каждый аннотирован профессиональными музыкантами через специализированный инструмент Sonic Visualiser. Аннотации включают:

\begin{itemize}
  \item \textbf{Beat positions} — временные метки долей такта.
  \item \textbf{Section labels} — типы структурных разделов (intro, verse, chorus, bridge, instrumental, outro и более тонкие подкатегории).
  \item \textbf{Downbeats} — сильные доли (начало тактов).
\end{itemize}

В нашей работе используется только секционная разметка. Из исходной 17-категорийной таксономии Harmonix мы свели к 6 классам:

\begin{lstlisting}
intro, intro_*           -> Intro
verse, verse_*, theme    -> Verse
bridge, transition_*     -> Bridge
chorus, chorus_*, hook   -> Chorus
instrumental, solo, breakdown -> Instrumental
outro, fadeout           -> Outro
\end{lstlisting}

\textbf{Доступность аудио.} Harmonix Set распространяется только с аннотациями, без аудио, по соображениям авторских прав. Аудио для каждого трека требуется получать самостоятельно. В рамках работы реализован пайплайн скачивания через \code{yt-dlp} по полю \code{youtube\_id} из метаданных датасета. Из 912 треков успешно загружено 743 (81.5\%); остальные удалены с YouTube или недоступны в регионе. Скрипт \code{scripts/download\_harmonix\_audio.py} автоматизирует процесс.

\subsubsection{GTZAN}

GTZAN~\cite{tzanetakis2002gtzan} — исторически первый датасет для жанровой классификации, опубликованный Tzanetakis и Cook в 2002 году. Содержит 1000 30-секундных wav-фрагментов в 10 жанровых категориях по 100 примеров: blues, classical, country, disco, hip-hop, jazz, metal, pop, reggae, rock. Мы получили 999 рабочих файлов (один файл повреждён в оригинальном архиве).

\textbf{Известные ограничения GTZAN}~\cite{sturm2014state}:

\begin{enumerate}
  \item \textbf{Дубликаты} — около 5\% треков повторяются под разными именами.
  \item \textbf{Ошибки маркировки} — особенно в категориях rock/country/blues.
  \item \textbf{Bias artist effect} — несколько исполнителей доминируют в каждой категории, что искажает оценку обобщения.
  \item \textbf{Устаревшая таксономия} — 10 жанров 2002 года не покрывают современные направления (electronic, indie, hip-hop subgenres, lo-fi).
\end{enumerate}

Несмотря на эти ограничения, GTZAN сохраняется как референсный датасет: за 23 года накопилась обширная литература сравнений, и переход на альтернативы (FMA, MagnaTagATune) лишил бы возможности прямого сопоставления с baseline-моделями. Обнаруженные в ходе работы ограничения out-of-distribution (поведение модели на современной музыке вне 10 GTZAN-категорий) явно адресуются в UI прототипа через top-3 классификации с предупреждением о низкой уверенности (см. §6.3).

\subsection{Извлечение признаков}\label{sec:3-2}

Все три датасета унифицируются на этапе feature extraction, который выполняется один раз и сохраняет результаты в формат \code{.npz} (сжатый numpy archive). Это позволяет последующее обучение использовать готовые признаки без повторного декодирования mp3, что критично для скорости epoch при многозадачном обучении.

\subsubsection{Окновая нарезка (windowing)}

Каждый трек разбивается на перекрывающиеся окна фиксированной длительности. Параметры:

\begin{itemize}
  \item \code{window\_seconds = 10.0} — длительность окна (10 секунд = 431 фрейм спектрограммы).
  \item \code{hop\_seconds = 1.0} — шаг между окнами (1 секунда между началами).
\end{itemize}

Выбор \code{window\_seconds = 10} обоснован двумя факторами. Во-первых, 10 секунд достаточно для типичного музыкального периода (один-два куплета или припев), что позволяет CNN модели «видеть» полный смысловой фрагмент. Во-вторых, AST-модель (см. §4.5) была предобучена на AudioSet с окнами 10 секунд, и сохранение этого размера позволяет напрямую использовать предобученные веса без интерполяции positional embeddings.

Шаг 1 секунда обеспечивает плотное покрытие аудио: за минуту получаем $\sim$50 окон, что даёт достаточную плотность для пост-обработки через Viterbi.

\subsubsection{Глобальная нормализация}

После извлечения признаков по всему обучающему сплиту вычисляются глобальные статистики mean и std по всем мел-полосам:

\begin{lstlisting}[language=Python]
features_train = np.concatenate([np.load(f)["features"] for f in train_files])
mean = features_train.mean(axis=(0, 2), keepdims=True)  # (1, n_mels, 1)
std = features_train.std(axis=(0, 2), keepdims=True) + 1e-6
np.savez("stats.npz", mean=mean, std=std)
\end{lstlisting}

Эти статистики применяются ко всем трём сплитам (train/val/test) перед подачей в модель: \code{(feat - mean) / std}. Без нормализации модель медленно сходится и выдаёт смещённые предсказания на новых треках. \textbf{Критическое требование} для inference: тот же \code{stats.npz} должен использоваться при обработке пользовательских аудиозагрузок — иначе предсказания будут систематически неверными. В нашем пайплайне \code{musicml/infer.py:extract\_features()} автоматически загружает \code{stats.npz} из стандартных путей.

\subsection{Стратегия разбиения train/val/test}\label{sec:3-3}

Каждый из трёх датасетов независимо разбивается в пропорции \textbf{70 / 15 / 15} (train / validation / test). Принципиальные решения:

\begin{enumerate}
  \item \textbf{Разбиение на уровне треков, не окон.} Если бы мы перемешали окна и разделили на сплиты, окна одного трека попадали бы и в train, и в test, что давало бы ложно-завышенные метрики из-за корреляции между соседними окнами. Разбиение на уровне треков гарантирует, что модель не «видит» test-треки при обучении.

  \item \textbf{Стратификация для GTZAN.} GTZAN строго сбалансирован (по 100 треков на жанр), стратификация выполняется автоматически при последовательном делении 70:15:15 = 70:15:15 треков на класс.

  \item \textbf{Стратификация для DEAM невозможна.} Поскольку каждый DEAM-трек имеет покадровые непрерывные аннотации, разные фрагменты одного трека могут принадлежать разным классам arousal/valence. Стратификация на уровне треков по сводной метке трека была бы артефициальна. Используется случайное разбиение с фиксированным seed=42.

  \item \textbf{Harmonix без стратификации по жанру.} Аннотации Harmonix не содержат явной жанровой информации. Разбиение случайное с тем же seed=42.

  \item \textbf{Воспроизводимость.} Список треков в каждом сплите сохраняется в \code{splits.json} при подготовке датасета, что позволяет воспроизвести точные сплиты в любой момент.
\end{enumerate}

\subsection{Дисбаланс классов}\label{sec:3-4}

Анализ распределения классов в train-сплитах выявил критический дисбаланс по сегментной задаче:

\begin{table}[H]
\centering
\caption{Таблица 3.2. Распределение классов в train-сплитах}
\begin{tabular}{L{3cm}L{3cm}L{3cm}L{4cm}}
\toprule
Задача & Класс & Доля окон & Inverse-frequency weight \\
\midrule
\textbf{Segment} & Verse & $\sim$35\% & 0.71 \\
 & Chorus & $\sim$25\% & 1.00 \\
 & Bridge & $\sim$12\% & 2.08 \\
 & Intro & $\sim$10\% & 2.50 (capped) \\
 & Instrumental & $\sim$10\% & 2.50 (capped) \\
 & Outro & $\sim$8\% & 2.50 (capped) \\
\textbf{Arousal} & Low / Mid / High & $\sim$33\% / 34\% / 33\% & $\approx 1.00$ каждый \\
\textbf{Valence} & Dark / Neutral / Bright & $\sim$33\% / 33\% / 34\% & $\approx 1.00$ каждый \\
\textbf{Genre} & каждый из 10 & $\sim$10\% & $\approx 1.00$ каждый \\
\bottomrule
\end{tabular}
\end{table}

Сегментная задача — единственная сильно несбалансированная: Verse и Chorus совокупно занимают $\sim$60\% окон, тогда как Outro — менее 10\%. Без специальной обработки модель с высокой вероятностью научится предсказывать только Verse и Chorus, игнорируя редкие классы.

Для устранения дисбаланса применяются три механизма:

\begin{enumerate}
  \item \textbf{Inverse-frequency class weights} — каждый класс получает вес, обратно пропорциональный его частоте, с верхним порогом \code{max\_class\_weight=2.5} (выбран эмпирически, чтобы избежать чрезмерного усиления редких классов; см. §4.6).

  \item \textbf{Focal Loss}~\cite{lin2017focal} — модификация cross-entropy с фокусом на сложные примеры через множитель $(1-p_t)^\gamma$ при $\gamma = 1.5$. Снижает вклад уверенных правильных предсказаний и усиливает сложные.

  \item \textbf{Per-task loss weight} — суммарный мульти-задачный loss балансируется через множитель \code{segment: 1.5} (остальные задачи: 1.0), компенсируя относительно меньший вклад structurial-задачи в общую функцию потерь из-за её большей сложности.
\end{enumerate}

Эксперимент с более агрессивными параметрами (\code{segment\_weight=3.5}, \code{focal\_gamma=2.5}, \code{max\_class\_weight=3.5}) показал противоположный эффект — модель переобучается на редкие классы и теряет качество на доминирующих (см. §5.5, неудачный эксперимент CNN v3).

\textbf{Резюме главы 3.} Описаны три исходных датасета, их характеристики и обоснование выбора. Описан унифицированный пайплайн извлечения log-mel признаков (128 bins, окна 10\,с / 1\,с шаг) с глобальной нормализацией. Описана стратегия разбиения train/val/test на уровне треков с фиксированным seed для воспроизводимости. Идентифицирована ключевая проблема — class imbalance в сегментной задаче, для которой предложены три механизма противодействия (class weights, focal loss, per-task loss weight).

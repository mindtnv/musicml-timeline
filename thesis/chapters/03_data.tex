\chapter{Данные}\label{ch:3}

Используются три открытых датасета, каждый специализированный под одну задачу: DEAM (эмоции), Harmonix Set (структура), GTZAN (жанр). Объединение разнородных корпусов в мульти-задачное обучение требует унифицированного пайплайна предобработки и аккуратных сплитов.

\textbf{DEAM}~\cite{aljanaki2017deam} — крупнейший открытый MER-датасет (MediaEval 2013–2018). 1802 фрагмента по 45\,с из Free Music Archive (CC-лицензия); покадровые аннотации arousal/valence получены через краудсорсинг ($\sim$10 аннотаторов на трек, шаг 500\,мс). Формат: \code{\{arousal,valence\}\_average.csv} (усреднённые ряды по 60 фреймам), \code{\_std.csv} (согласие аннотаторов), \code{metadata.csv}. Непрерывные значения $[-1,+1]$ дискретизируются в 3 категории по порогам $\pm 0.2$:

\begin{lstlisting}
arousal: [-1.0..-0.2] -> Low, [-0.2..+0.2] -> Mid, [+0.2..+1.0] -> High
valence: [-1.0..-0.2] -> Dark, [-0.2..+0.2] -> Neutral, [+0.2..+1.0] -> Bright
\end{lstlisting}

Пороги $\pm 0.2$ обеспечивают приблизительно равномерное распределение (25–40\% на класс) и сохраняют семантику (Low при arousal$\approx 0$ не был бы «действительно низкой энергией» при разбиении по квантилям).

\textbf{Harmonix Set}~\cite{nieto2019harmonix} — единственный крупный открытый датасет структурной разметки коммерческой поп-музыки (912 треков, ручная разметка в Sonic Visualiser). Аннотации включают beat positions, section labels, downbeats; используются только секции. Исходные 17 категорий сведены к 6:

\begin{lstlisting}
intro, intro_*           -> Intro
verse, verse_*, theme    -> Verse
bridge, transition_*     -> Bridge
chorus, chorus_*, hook   -> Chorus
instrumental, solo, breakdown -> Instrumental
outro, fadeout           -> Outro
\end{lstlisting}

Harmonix распространяется без аудио (copyright); реализован пайплайн скачивания через \code{yt-dlp} по \code{youtube\_id} (\code{scripts/download\_harmonix\_audio.py}). Из 912 треков загружено 743 (81.5\%); остальные удалены с YouTube.

\textbf{GTZAN}~\cite{tzanetakis2002gtzan} — 999 рабочих файлов (1 повреждён) в 10 жанрах по 100 примеров: blues, classical, country, disco, hip-hop, jazz, metal, pop, reggae, rock. Известные ограничения~\cite{sturm2014state}: дубликаты ($\sim$5\%), ошибки маркировки, artist bias, устаревшая таксономия. Несмотря на это, GTZAN сохраняется как референс ради сопоставимости с 23-летней литературой; OOD-поведение адресуется через top-3 UI в прототипе (§6.3).

\section{Извлечение признаков}\label{sec:3-2}

Все датасеты унифицируются на этапе feature extraction и сохраняются в \code{.npz}: это позволяет обучению не перекодировать mp3 каждый раз, что критично для скорости epoch.

Логарифмическая компрессия: \code{librosa.power\_to\_db(..., ref=np.max)} $\to$ диапазон $\approx [-80, 0]$\,дБ.

\textbf{Окновая нарезка.} \code{window\_seconds = 10.0} (431 фрейм), \code{hop\_seconds = 1.0}. Выбор 10\,с обоснован двумя факторами: (1) достаточно для типичного музыкального периода (куплет/припев); (2) AST предобучен на 10-секундных окнах AudioSet, что позволяет использовать веса без интерполяции positional embeddings. Шаг 1\,с даёт $\sim$50 окон/минуту — достаточно для Viterbi.

\textbf{Глобальная нормализация.} По train split вычисляются mean/std по мел-полосам и сохраняются в \code{stats.npz}:

\begin{lstlisting}[language=Python]
features_train = np.concatenate([np.load(f)["features"] for f in train_files])
mean = features_train.mean(axis=(0, 2), keepdims=True)  # (1, n_mels, 1)
std = features_train.std(axis=(0, 2), keepdims=True) + 1e-6
np.savez("stats.npz", mean=mean, std=std)
\end{lstlisting}

Применяются ко всем сплитам: \code{(feat - mean) / std}. \textbf{Критично:} тот же \code{stats.npz} используется при inference пользовательских загрузок — \code{musicml/infer.py:extract\_features()} загружает его автоматически.

\section{Стратегия разбиения train/val/test}\label{sec:3-3}

Каждый датасет независимо разбивается \textbf{70/15/15} с seed=42. Принципиальные решения: (1) разбиение \textbf{на уровне треков, не окон} — иначе окна одного трека попадали бы и в train, и в test, что завышает метрики; (2) GTZAN стратифицирован автоматически (100 треков/класс); (3) для DEAM стратификация невозможна (покадровые непрерывные метки, разные фрагменты одного трека принадлежат разным классам) — используется случайное разбиение; (4) Harmonix — случайное, жанровая информация отсутствует; (5) списки треков каждого сплита сохраняются в \code{splits.json} для воспроизводимости.

Сегментная задача — единственная сильно несбалансированная (Verse+Chorus $\sim$60\%, Outro $<10$\%). Без обработки модель выучит только доминирующие классы. Применяются три механизма: (1) \textbf{inverse-frequency class weights} с порогом \code{max\_class\_weight=2.5} (эмпирически, против чрезмерного усиления редких классов; §4.6); (2) \textbf{Focal Loss}~\cite{lin2017focal} с $\gamma=1.5$ — множитель $(1-p_t)^\gamma$ снижает вклад уверенных правильных предсказаний; (3) \textbf{per-task loss weight} \code{segment: 1.5} (остальные: 1.0). Более агрессивные параметры (\code{segment\_weight=3.5}, \code{focal\_gamma=2.5}, \code{max\_class\_weight=3.5}) дали обратный эффект — переобучение на редкие классы (§5.5, неудачный CNN v3).

\textbf{Резюме главы 3.} Описаны три датасета, унифицированный log-mel пайплайн (128 bins, окна 10\,с / 1\,с) с глобальной нормализацией, и стратегия разбиения на уровне треков с seed=42. Для сегментной задачи применены три механизма борьбы с дисбалансом: class weights, focal loss, per-task loss weight.

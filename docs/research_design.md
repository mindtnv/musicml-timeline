# Дизайн исследования: 2×2 факторный эксперимент

## Формулировка из НИР

> **Цель**: создание прототипа системы автоматического анализа музыкальных композиций, способной по входному аудиотреку формировать временную разметку с типами сегментов, уровнем энергии и характером настроения

> **Направление**: исследование комбинации классических музыкальных признаков (мел-спектрограмма, MFCC, chroma, энергетика) с свёрточными нейронными сетями и **оценка влияния выбранных признаков и архитектуры** на качество сегментации и эмоциональной классификации

## Исследовательские вопросы

1. **RQ1**: Насколько эффективна мульти-задачная CNN для одновременного определения структурных сегментов, уровня энергии и настроения?
2. **RQ2**: Какой вклад вносит temporal modeling (BiLSTM) в качество предсказаний по сравнению с per-window классификацией?
3. **RQ3**: Какой вклад вносит качество признаков (pretrained vs from-scratch) при одинаковой архитектуре?
4. **RQ4**: Какой фактор (temporal context или quality of features) оказывает большее влияние на качество анализа?

## 2×2 факторный дизайн

|  | Per-window (без контекста) | Sequence (BiLSTM) |
|---|---|---|
| **From scratch (наша CNN)** | **Конфиг 1** — BASELINE | **Конфиг 2** — CNN + BiLSTM |
| **Pretrained (PANNs CNN14)** | **Конфиг 3** — PANNs + Linear | **Конфиг 4** — PANNs + BiLSTM |

### Что изолирует каждое сравнение

- **Фактор A — Temporal modeling**: Конфиг 2 vs 1, Конфиг 4 vs 3
  → Показывает вклад BiLSTM (контекст последовательности окон)

- **Фактор B — Feature quality**: Конфиг 3 vs 1, Конфиг 4 vs 2
  → Показывает вклад pretrained features (PANNs CNN14 vs наша CNN)

- **Взаимодействие факторов**: (Конфиг 4 - Конфиг 3) vs (Конфиг 2 - Конфиг 1)
  → Показывает, усиливают ли факторы друг друга (синергия) или нет

## Описание конфигураций

### Конфиг 1: CNN (baseline) — уже реализован
- **Backbone**: Conv2D(32→64→128→256) + BN + ReLU + SE-Block + MaxPool + GAP
- **Features**: log-mel spectrogram (128 bins, 8s окно)
- **Обработка**: каждое окно независимо → (B, 1, 128, 344) → (B, 256) → heads
- **Heads**: Linear(256 → n_classes) для каждой задачи
- **Параметры**: ~250K, dropout=0.4, AdamW + OneCycleLR, Focal Loss, SpecAugment, Mixup

### Конфиг 2: CNN + BiLSTM — наш главный вклад
- **Backbone**: та же CNN → (N, 256) embeddings per window
- **Temporal model**: BiLSTM(input=256, hidden=128, layers=2, bidirectional) → (N, 256)
- **Обработка**: все окна трека как последовательность → BiLSTM → per-window predictions с контекстом
- **Heads**: Linear(256 → n_classes)
- **Новизна**: добавление temporal context к нашей from-scratch архитектуре

### Конфиг 3: PANNs + Linear (per-window)
- **Backbone**: PANNs CNN14 (frozen, pretrained на AudioSet 5000h) → (N, 2048)
- **Temporal model**: нет, per-window
- **Heads**: Linear(2048 → n_classes)
- **Цель**: изолировать эффект качества признаков без temporal context

### Конфиг 4: PANNs + BiLSTM
- **Backbone**: PANNs CNN14 (frozen) → (N, 2048)
- **Projection**: Linear(2048 → 512)
- **Temporal model**: BiLSTM(input=512, hidden=256, layers=2, bidirectional) → (N, 512)
- **Heads**: Linear(512 → n_classes)
- **Цель**: верхняя граница — лучшие features + temporal context

## Baseline результаты (Конфиг 1 — уже получены)

| Задача | Accuracy | Macro F1 |
|--------|----------|----------|
| Segment | 24.5% | 22.9% |
| Arousal | 66.8% | 65.9% |
| Valence | 56.0% | 54.1% |
| Genre | 82.5% | 81.7% |

Проблемы на реальных треках:
- Жанр прыгает между окнами (нет consistency)
- Сегментация: модель предсказывает Intro/Outro почти везде
- Валентность: застревает на Dark

## Научная ценность

1. **Конфиг 1** (CNN) — baseline, полностью наша разработка, демонстрация мульти-задачного подхода
2. **Конфиг 2** (CNN + BiLSTM) — **основной вклад**: оригинальная архитектура, 100% наша
3. **Конфиг 3** (PANNs + Linear) — reference для оценки влияния quality of features
4. **Конфиг 4** (PANNs + BiLSTM) — upper bound, показывает потенциал комбинации

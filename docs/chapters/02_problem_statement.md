# Глава 2. Постановка задачи

## 2.1 Цель исследования

Целью настоящей работы является создание прототипа программно-аналитической системы автоматического анализа музыкальных композиций, формирующей по входному аудиотреку **многоаспектную временную разметку** (timeline) с четырьмя категориями признаков:

1. **Структурная сегментация** — отнесение каждого временного интервала к одной из шести категорий музыкальной формы: вступление (Intro), куплет (Verse), бридж (Bridge), припев (Chorus), инструментальная часть (Instrumental), завершение (Outro).
2. **Уровень энергии (arousal)** — оценка субъективной активности музыки в трёх категориях: низкая (Low), средняя (Mid), высокая (High).
3. **Эмоциональная окраска (valence)** — оценка субъективной приятности музыки в трёх категориях: тёмная (Dark), нейтральная (Neutral), светлая (Bright).
4. **Жанр (genre)** — отнесение трека к одному из десяти жанров: блюз, классика, кантри, диско, хип-хоп, джаз, метал, поп, регги, рок.

В отличие от существующих специализированных решений, ориентированных на одну из четырёх задач (Madmom для onset detection, Essentia для feature extraction, MIRtoolbox для академических исследований [30, 31, 32]), предлагаемая система решает **все четыре задачи одновременно** через единую модель. Это обеспечивает:

- **Согласованность результатов** — структурные границы синхронизированы с эмоциональными переходами, поскольку обе оценки производятся на общих признаках.
- **Эффективность вычислений** — однократный проход аудио через сеть вместо четырёх независимых анализов.
- **Возможность совместной интерпретации** — например, переход от куплета к припеву типично сопровождается ростом arousal, что система отображает в синхронизированных таймлайнах прототипа (см. §6.2).

### 2.1.1 Формальная постановка

Пусть $x \in \mathbb{R}^{T_{\text{audio}}}$ — моноаудиосигнал с частотой дискретизации $sr = 22050$ Гц. Извлечение признаков преобразует его в последовательность лог-мел спектрограммных окон $X = \{X_1, \dots, X_N\}$, где $X_i \in \mathbb{R}^{F \times W}$, $F = 128$ — число мел-полос, $W = sr \cdot \tau / h$ — число фреймов в окне длительностью $\tau = 10$ с при hop $h = 512$ семплов.

Модель $f_\theta$ с параметрами $\theta$ выдаёт для каждого окна $X_i$ четыре независимых распределения:

$$
f_\theta(X_i) = \big( p^{\text{seg}}_i, \; p^{\text{aro}}_i, \; p^{\text{val}}_i, \; p^{\text{gen}}_i \big),
$$

где $p^{\text{seg}}_i \in \Delta^5$ (симплекс над 6 классами сегментов), $p^{\text{aro}}_i, p^{\text{val}}_i \in \Delta^2$ (3-классовые), $p^{\text{gen}}_i \in \Delta^9$ (10-классовый).

Финальная разметка строится через post-processing функцию $g$, преобразующую покадровые предсказания в непрерывные интервалы:

$$
g\big( \{p_i\}_{i=1}^N \big) \mapsto \{ (t_j^{\text{start}}, t_j^{\text{end}}, c_j, \kappa_j) \}_{j=1}^M,
$$

где $c_j$ — класс сегмента, $\kappa_j$ — confidence (средняя вероятность класса по фреймам сегмента), $M$ — число сегментов после слияния. Подробное описание $g$ (Viterbi + position priors + min-duration merge) приводится в §4.7.

## 2.2 Исследовательские вопросы

В рамках работы исследуются пять вопросов, раскрывающих архитектурные альтернативы и пост-обработку:

**RQ1.** Насколько эффективна мульти-задачная CNN-модель для одновременного решения четырёх задач анализа музыки на ограниченных датасетах (~2.5 тыс. треков суммарно)? Достигает ли она качества, сопоставимого со специализированными однозадачными моделями из литературы?

**RQ2.** Какой вклад вносит **temporal modeling** через BiLSTM-слой поверх per-window CNN-эмбеддингов? Улучшает ли учёт долгосрочного контекста результаты структурной сегментации, где порядок сегментов имеет значение?

**RQ3.** Какой вклад вносит **качество входных признаков** через использование PANNs CNN14, предобученных на AudioSet (≈2 млн аудиофрагментов), в сравнении с обучаемой с нуля CNN? Достаточен ли AudioSet pretraining для transfer learning на MIR-задачи?

**RQ4.** Какой из двух факторов — temporal modeling (BiLSTM) или quality of features (pretraining) — оказывает большее влияние на итоговое качество? Влияние интерактивно или аддитивно?

**RQ5.** Способна ли архитектура **Audio Spectrogram Transformer** (AST), pretrained на AudioSet, превзойти CNN- и PANNs-baseline за счёт глобального self-attention и более богатой инициализации? Какие задачи она улучшает в наибольшей степени, и с какими trade-off?

Первые четыре вопроса (RQ1–RQ4) формируют 2×2 факторный эксперимент с четырьмя конфигурациями (CNN, CNN+BiLSTM, PANNs+Linear, PANNs+BiLSTM). RQ5 расширяет эксперимент пятой архитектурой (AST), вводя transformer-парадигму. Дополнительно проводится ablation post-processing (с/без Viterbi и position priors) для оценки вклада musicological priors.

## 2.3 Обоснование мульти-задачного подхода

Решение четырёх задач единой моделью обосновывается тремя группами аргументов:

### 2.3.1 Семантические корреляции между задачами

Музыкальные явления, описываемые четырьмя категориями признаков, статистически коррелируют:

- **Жанр определяет типичную структуру**: рок-композиции имеют чётко выраженную verse–chorus форму, классическая музыка следует sonata-form или rondo, электронная — секциям intro–build-up–drop. Знание жанра помогает модели предсказывать вероятные структурные паттерны.
- **Эмоциональная динамика согласована со структурой**: переход куплет → припев типично сопровождается ростом arousal (плотности атак, громкости) и сменой valence (более «светлым» гармоническим окрасом). Predictions emotion и segment должны быть взаимно-консистентны.
- **Жанр коррелирует с эмоцией**: metal статистически чаще тёмный и активный (Q2 квадрант Russell), classical — спокойный и позитивный (Q4), blues — спокойный и тёмный (Q3). Эти статистики дают модели полезный prior.

### 2.3.2 Регуляризация через shared backbone

Мульти-задачное обучение действует как **формa регуляризации**, особенно ценная при ограниченном объёме данных. Общий backbone вынужден извлекать представления, полезные для всех четырёх задач одновременно — что препятствует переобучению на специфике одной задачи. Это соответствует принципу **representation learning**: универсальные признаки (тембр, ритм, гармония) более робастны, чем task-specific признаки (например, специфические артефакты Harmonix-разметки).

Эмпирически в данной работе MTL-модель показывает better generalization gap (разрыв между train- и val-accuracy) на 3–5 пп, чем сравнимые single-task baseline (см. ablation в §5.7).

### 2.3.3 Практическая ценность для пользователя

С точки зрения конечного приложения (визуализатор музыкального анализа, ритм-игра, рекомендательная система), пользователю необходимы **все четыре аспекта одновременно**. Альтернативы — последовательный запуск четырёх независимых моделей — приводит к:

- Четырёхкратному увеличению времени inference (8 с × 4 = 32 с на 3-минутный трек вместо 8 с).
- Несогласованности результатов (4 модели не «знают» друг о друге).
- Усложнению развертывания (4 checkpoint вместо одного, 4 запуска препроцессинга).

Единая мульти-задачная модель выдаёт согласованную разметку за один проход, что критично для интерактивных приложений типа реализованного в работе веб-дашборда (Глава 6).

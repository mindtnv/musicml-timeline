# Глава 5. Эксперименты

В рамках работы проведено четыре последовательных эксперимента: (5.3) baseline-запуск всех четырёх архитектур 2×2 факторного дизайна (v1); (5.4) улучшенный запуск с обновлёнными гиперпараметрами (v2); (5.5) расширение трансформер-архитектурой AST v2; (5.6) попытка дальнейшего улучшения через агрессивный CNN v3 retrain (failed experiment, документируется как академически честный negative result). Дополнительно проведён (5.8) ablation post-processing pipeline для оценки вклада Viterbi-декодирования и position priors.

## 5.1 Протокол оценки

### 5.1.1 Метрики

Каждая из четырёх классификационных задач оценивается тремя стандартными метриками:

- **Accuracy** — доля корректно классифицированных окон. Простая, но искажается дисбалансом классов.
- **Macro-averaged F1** — среднее арифметическое F1 по всем классам без учёта частоты. Более честная метрика при несбалансированных датасетах.
- **Per-class precision / recall / F1** — детальное разложение по классам, позволяющее идентифицировать какие именно классы плохо распознаются.

Дополнительно для сегментной задачи измеряется:

- **Boundary F1 ±3 секунды** — стандартная метрика MIR для оценки качества обнаружения структурных переходов. Граница считается корректной, если предсказанная не более чем на 3 секунды отклоняется от правильной.

### 5.1.2 Train/val/test протокол

- **Splits**: 70/15/15 на уровне треков, фиксированный seed=42 (см. §3.3).
- **Размеры test-сетов**: DEAM ≈11.6K окон, Harmonix ≈23.4K окон, GTZAN ≈3.2K окон.
- **Eval после обучения**: модель загружается из ckpt с лучшим val_loss; eval на test выполняется один раз.
- **Воспроизводимость**: все random seeds зафиксированы; результаты воспроизводимы при повторном запуске.

### 5.1.3 Random baselines

Для интерпретации абсолютных значений приведены random baselines (равновероятный выбор класса):

| Задача | Классов | Random baseline accuracy |
|---|---|---|
| Segment | 6 | 16.7% |
| Arousal | 3 | 33.3% |
| Valence | 3 | 33.3% |
| Genre | 10 | 10.0% |

## 5.3 Эксперимент v1 (baseline-запуск)

### 5.3.1 Конфигурация v1

Первая версия моделей обучалась с консервативными параметрами:
- 4 conv-блока в CNN backbone (без 5-го уровня).
- 30 эпох, OneCycleLR.
- focal_gamma = 2.0 (агрессивный фокус на сложных).
- max_class_weight = 4.0 (полная inverse-frequency компенсация).
- window = 8 секунд.

### 5.3.2 Результаты v1

**Таблица 5.1. Результаты 2×2 эксперимента (v1)**

| Конфигурация | Segment acc/F1 | Arousal acc/F1 | Valence acc/F1 | Genre acc/F1 |
|---|---|---|---|---|
| CNN per-window | 24.3 / 23.1 | 65.9 / 65.3 | 55.8 / 53.4 | 82.7 / 81.9 |

### 5.3.3 Диагностика проблем v1

**Сегментная задача (24.3% CNN).** Per-class разбор показал критический дефект — модель подавляет мажоритарные классы:

| Класс | Precision | Recall | F1 | Интерпретация |
|---|---|---|---|---|
| Intro | 28.9 | 64.2 | 39.8 | Overpredicted |
| Verse | 68.9 | **10.1** | 17.6 | Почти не предсказывается |
| Bridge | 19.2 | 51.5 | 28.0 | Overpredicted |
| Chorus | 70.9 | **18.4** | 29.2 | Почти не предсказывается |
| Instrumental | 10.0 | 62.5 | 17.3 | Overpredicted, низкая precision |
| Outro | 4.1 | 14.4 | 6.4 | Плох по всем метрикам |

Диагноз: `max_class_weight=4.0` чрезмерно усиливал миноритарные классы — модель «перестраховывалась», предсказывая Intro/Bridge/Instrumental вместо Verse/Chorus, поскольку ошибка на миноритарном классе стоила в 4 раза дороже.

**CNN+BiLSTM на жанре (45.5%).** Катастрофическое переобучение: train accuracy >90%, val ≈ 45%. Причина — BiLSTM с ~400K параметров обучался на 699 GTZAN-треках, недостаточно для генерализации. Per-window CNN не страдал от этого, поскольку видел ~16K окон.

### 5.4.5 Ответы на RQ1–RQ4

**RQ1 (мульти-задачная CNN).** Ответ положительный: одна модель эффективно решает 4 задачи, особенно сильно на Genre (83.9% — на уровне специализированных моделей в literature) и Arousal (62%). Сегментация остаётся слабой (35.3%) — в пределах типичных результатов 6-классовой section labeling в literature [10, 11].

**RQ2 (temporal modeling).** Ответ ограниченно положительный: BiLSTM улучшает arousal (CNN: 62 → CNN+BiLSTM: 62.3) и valence (51.7 → 54.2), но **вредит** genre (83.9 → 60.9 для CNN+BiLSTM). Причина — переобучение BiLSTM на малой выборке Harmonix-треков. Для PANNs+BiLSTM эффект менее выражен (frozen backbone снижает риск переобучения).

**RQ3 (качество признаков).** Ответ удивительный: **PANNs не дают преимущества** перед обучаемой с нуля CNN на большинстве задач. PANNs+Linear хуже CNN на сегменте (24 vs 35.3) и сравним на остальных. Гипотеза: AudioSet pretraining оптимизирован под звуковые события (звон, шум, голос), что не идеально для музыкального анализа. Дополнительная проверка через AST (см. §5.5) показывает, что pretraining помогает только при возможности fine-tuning.

**RQ4 (фактор больше влияния).** Ни один из двух факторов 2×2 эксперимента не оказался решающим. Лучший на сегменте — PANNs+BiLSTM (32.9), на arousal/valence — он же. На genre — CNN per-window (83.9). Различия меньше 3 п.п. между лучшим и средним. Реальный прорыв пришёл с третьей архитектурной парадигмой — трансформерами (AST, см. §5.5).

## 5.5 Эксперимент AST v2 (расширение трансформер-архитектурой)

### 5.5.1 Мотивация

После 2×2 эксперимента стало очевидно: ни CNN, ни PANNs не дают качественного скачка. Гипотеза — необходима архитектура с **глобальным receptive field** (как BiLSTM) **и** богатой инициализацией (как PANNs), но более ёмкая и адаптируемая. AST [25] удовлетворяет обоим требованиям: self-attention видит всю спектрограмму, AudioSet-pretraining обеспечивает богатую инициализацию, частичная заморозка позволяет fine-tuning без catastrophic forgetting.

### 5.5.2 Конфигурация AST v2

- Базовая модель: `MIT/ast-finetuned-audioset-10-10-0.4593` (87M параметров).
- Заморожены: patch embedding + первые 8 из 12 transformer-слоёв.
- Trainable: верхние 4 слоя + heads + CLS-токен ≈ 14.4M параметров.
- Differential lr: backbone 5e-5, heads 1e-3, weight_decay 0.01.
- batch_size = 16, gradient_accumulation = 4 (effective batch = 64).
- 30 эпох, patience 10, scheduler — CosineAnnealingWarmRestarts(T_0=10, T_mult=2).

Время обучения: ~3 часа на одном GPU (12GB VRAM). Существенно дольше CNN v2 (~3.5 ч), что сравнимо с PANNs+BiLSTM (~5 ч с учётом precompute embeddings).

### 5.5.3 Результаты AST v2

**Таблица 5.5. Результаты AST v2 (test-сет)**

| Задача | Accuracy | Macro-F1 | Δ vs CNN v2 (acc) |
|---|---|---|---|
| **Segment** | **40.6** | **30.8** | **+5.3 п.п.** |
| Arousal | 60.6 | 60.4 | −1.4 п.п. |
| Valence | 51.1 | 50.4 | −0.6 п.п. |
| Genre | 81.5 | 80.8 | −2.4 п.п. |
| **Среднее** | **58.5** | 55.6 | **+0.3 п.п.** |

**Per-class сегмент:**

| Класс | Precision | Recall | F1 |
|---|---|---|---|
| Intro | 31.0 | 50.0 | 38.3 |
| Verse | 51.0 | 45.7 | 48.2 |
| Bridge | 20.1 | 22.9 | 21.4 |
| Chorus | 48.2 | 45.6 | 46.9 |
| Instrumental | 26.6 | 23.4 | 24.9 |
| Outro | 4.5 | 6.1 | 5.2 |

### 5.5.4 Ответ на RQ5

AST v2 действительно превзошёл CNN-baseline по сегментной задаче (+5.3 п.п. accuracy). Главный источник прироста — более сбалансированные предсказания на Verse (recall 45.7% vs 27.9% у CNN v2) и Chorus (45.6% vs 40.3%). Это подтверждает гипотезу о ценности глобального self-attention для распознавания повторяющихся структурных паттернов.

Однако AST v2 уступил CNN v2 на genre (−2.4 п.п.). Причина — для 10-классовой genre classification на 30-секундных GTZAN-фрагментах глобальный контекст менее ценен (фрагмент уже короток), а CNN с inductive bias (translation invariance) более эффективен.

**Ключевой trade-off:** AST v2 даёт лучший средний результат и драматически лучше на сегменте, но требует в 30 раз больше памяти (574 MB vs 21 MB checkpoint) и в 4 раза больше времени inference (8 с vs 2 с на 3-минутный трек). Для прототипа выбран AST v2 — приоритет качества над эффективностью.

## 5.6 Эксперимент CNN v3 (failed retrain)

### 5.6.1 Мотивация

После выявления слабого сегмента у CNN v2 (35.3%) выдвинута гипотеза: **усиление сегментной задачи** через более агрессивные веса даст +3–7 п.п. accuracy.

### 5.6.2 Конфигурация CNN v3

| Параметр | CNN v2 | **CNN v3** |
|---|---|---|
| segment_weight | 1.5 | **3.5** |
| focal_gamma | 1.5 | **2.5** |
| max_class_weight | 2.5 | **3.5** |
| Остальное | — | без изменений |

Гипотеза: тройное усиление (loss weight × focal gamma × class weight) перенаправит больше градиента в сторону редких сегментных классов, улучшая Verse/Chorus/Instrumental без ущерба для остальных задач.

### 5.6.3 Результаты CNN v3

**Таблица 5.6. CNN v3 vs CNN v2**

| Задача | CNN v2 | **CNN v3** | Δ |
|---|---|---|---|
| Segment | 35.3 | **22.1** | **−13.2 п.п.** |
| Arousal | 62.0 | 64.5 | +2.5 |
| Valence | 51.7 | 54.1 | +2.4 |
| Genre | 83.9 | 79.1 | −4.8 |
| **Среднее** | 58.2 | 54.9 | **−3.3 п.п.** |

### 5.6.4 Анализ провала

CNN v3 показал противоположный эффект — сегмент **упал** на 13.2 п.п. Анализ training log выявил причины:

1. **Early stopping на эпохе 19**, лучший val_loss достигнут уже на эпохе 4, дальше только ухудшение. Модель быстро переобучилась на редкие сегментные классы.
2. **Class weights после обрезания**: `[Intro: 3.05, Verse: 0.44, Bridge: 1.14, Chorus: 0.47, Instrumental: 3.5, Outro: 3.5]`. Соотношение Intro/Verse теперь 7:1 — модель «карается» за ошибку на Intro в 7 раз сильнее, чем на Verse. Это сместило её в сторону overprediction редких классов.
3. **Деградация genre на 4.8 п.п.** — следствие мульти-задачной природы: чрезмерная оптимизация одной головы (segment weight 3.5) забирает ёмкость backbone у других.

### 5.6.5 Что мы извлекли

CNN v3 — **академически ценный negative result**:

- Подтверждает, что v2 уже находится в окрестности оптимума для CNN-архитектуры.
- Показывает, что class imbalance невозможно «решить» простым увеличением весов — нужен либо больше данных (что недоступно), либо лучшая архитектура (что и сделал AST v2).
- Демонстрирует риск aggressive reweighting в multi-task контексте: усиление одной задачи деградирует остальные.

Этот результат включён в отчёт как иллюстрация научной добросовестности — публикация неудачных экспериментов также является вкладом в literature.

## 5.8 Ablation: вклад post-processing pipeline

Для оценки вклада каждого компонента pipeline (см. §4.7) проведено ablation на test-сете Harmonix с моделью AST v2:

**Таблица 5.8. Ablation post-processing**

| Метод | Сегментов в треке (avg) | Boundary F1 ±3с | Section F1 |
|---|---|---|---|
| Argmax (без post-processing) | 28.4 | 0.31 | 0.32 |
| + Median filter (kernel=5) | 14.2 | 0.36 | 0.34 |
| + Viterbi (λ=1.0) | 9.8 | 0.42 | 0.37 |
| + Position priors (penalty=10) | 8.7 | 0.43 | 0.38 |
| + Min-duration merge (6 с) | 7.5 | 0.45 | 0.39 |

**Выводы:**

1. **Argmax без обработки даёт 28 сегментов на трек** — невозможно для пользователя интерпретировать. Полный pipeline сокращает до 7.5 сегментов — близко к реальному числу музыкальных секций (5–10).

2. **Viterbi даёт максимальный прирост Boundary F1**: +6 п.п. относительно median filter. Это подтверждает, что глобальная оптимизация последовательности эффективнее локального сглаживания.

3. **Position priors дают +1 п.п.** — небольшой, но устраняют грубые ошибки (Intro в середине трека), критически влияющие на user perception.

4. **Min-duration merge даёт +2 п.п.** — устраняет короткие шумовые сегменты.

5. **Полный pipeline +14 п.п. Boundary F1 / +7 п.п. Section F1** относительно сырых argmax-предсказаний.

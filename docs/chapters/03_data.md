# Глава 3. Данные

В работе используются три открытых датасета, каждый специализированный под одну из решаемых задач: DEAM (эмоции), Harmonix Set (структура), GTZAN (жанр). Объединение трёх разнородных корпусов в единое мульти-задачное обучение требует унифицированного пайплайна предобработки и аккуратного формирования сплитов. Настоящая глава описывает каждый датасет, обоснование выбора, схему предобработки признаков и принятый подход к балансировке классов.

## 3.1 Используемые датасеты

Сводная характеристика трёх датасетов приведена в таблице 3.1.

**Таблица 3.1. Используемые датасеты**

|---|---|---|---|---|---|

### 3.1.1 DEAM (Database for Emotional Analysis of Music)

DEAM — крупнейший открытый датасет для music emotion recognition, подготовленный в рамках серии MediaEval challenges 2013–2018 годов [15]. Содержит 1802 музыкальных фрагмента длительностью 45 секунд, выбранных из Free Music Archive с лицензией Creative Commons. Покадровые аннотации arousal и valence получены через краудсорсинговый эксперимент: каждый фрагмент оценивали в среднем 10 аннотаторов с шагом 500 мс.

**Формат аннотаций.** Для каждого трека предоставляется:

- `valence_average.csv`, `arousal_average.csv` — усреднённые временные ряды по 60 фреймам (30 секунд × 2 фрейма/с).
- `valence_std.csv`, `arousal_std.csv` — стандартные отклонения по аннотаторам, индикатор согласия.
- `metadata.csv` — общая информация о треках (длительность, BPM при наличии).

**Дискретизация.** Непрерывные значения arousal/valence в диапазоне [−1, +1] преобразуются в три категории по двум порогам, выбранным на основе анализа распределений в обучающей выборке:

```
arousal:    [-1.0 .. -0.2] → Low,    [-0.2 .. +0.2] → Mid,    [+0.2 .. +1.0] → High
valence:    [-1.0 .. -0.2] → Dark,   [-0.2 .. +0.2] → Neutral, [+0.2 .. +1.0] → Bright
```

Пороги ±0.2 выбраны как обеспечивающие приблизительно равномерное распределение классов на train split: каждый из трёх классов получает 25–40% примеров. Альтернативная схема равных квантилей (по 33% на класс) была отвергнута, поскольку нарушала бы семантическое соответствие («Low» при arousal=0 нельзя интерпретировать как действительно низкую энергию).

### 3.1.2 Harmonix Set

Harmonix Set [33] — единственный крупный открытый датасет со структурной разметкой коммерческой популярной музыки. Включает 912 треков, каждый аннотирован профессиональными музыкантами через специализированный инструмент Sonic Visualiser. Аннотации включают:

- **Beat positions** — временные метки долей такта.
- **Section labels** — типы структурных разделов (intro, verse, chorus, bridge, instrumental, outro и более тонкие подкатегории).
- **Downbeats** — сильные доли (начало тактов).

В нашей работе используется только секционная разметка. Из исходной 17-категорийной таксономии Harmonix мы свели к 6 классам:

```
intro, intro_*           → Intro
verse, verse_*, theme    → Verse
bridge, transition_*     → Bridge
chorus, chorus_*, hook   → Chorus
instrumental, solo, breakdown → Instrumental
outro, fadeout           → Outro
```

**Доступность аудио.** Harmonix Set распространяется только с аннотациями, без аудио, по соображениям авторских прав. Аудио для каждого трека требуется получать самостоятельно. В рамках работы реализован пайплайн скачивания через `yt-dlp` по полю `youtube_id` из метаданных датасета. Из 912 треков успешно загружено 743 (81.5%); остальные удалены с YouTube или недоступны в регионе. Скрипт `scripts/download_harmonix_audio.py` автоматизирует процесс.

### 3.1.3 GTZAN

GTZAN [19] — исторически первый датасет для жанровой классификации, опубликованный Tzanetakis и Cook в 2002 году. Содержит 1000 30-секундных wav-фрагментов в 10 жанровых категориях по 100 примеров: blues, classical, country, disco, hip-hop, jazz, metal, pop, reggae, rock. Мы получили 999 рабочих файлов (один файл повреждён в оригинальном архиве).

**Известные ограничения GTZAN** [20]:

1. **Дубликаты** — около 5% треков повторяются под разными именами.
2. **Ошибки маркировки** — особенно в категориях rock/country/blues.
3. **Bias artist effect** — несколько исполнителей доминируют в каждой категории, что искажает оценку обобщения.
4. **Устаревшая таксономия** — 10 жанров 2002 года не покрывают современные направления (electronic, indie, hip-hop subgenres, lo-fi).

Несмотря на эти ограничения, GTZAN сохраняется как референсный датасет: за 23 года накопилась обширная литература сравнений, и переход на альтернативы (FMA, MagnaTagATune) лишил бы возможности прямого сопоставления с baseline-моделями. Обнаруженные в ходе работы ограничения out-of-distribution (поведение модели на современной музыке вне 10 GTZAN-категорий) явно адресуются в UI прототипа через top-3 классификации с предупреждением о низкой уверенности (см. §6.3).

## 3.2 Извлечение признаков

Все три датасета унифицируются на этапе feature extraction, который выполняется один раз и сохраняет результаты в формат `.npz` (сжатый numpy archive). Это позволяет последующее обучение использовать готовые признаки без повторного декодирования mp3, что критично для скорости epoch при многозадачном обучении.

### 3.2.1 Конфигурация спектрограммы

Для каждого аудиофайла вычисляется log-mel спектрограмма со следующими параметрами:

| Параметр | Значение | Обоснование |
|---|---|---|
| Sample rate | 22050 Гц | Стандарт librosa, покрывает диапазон до 11025 Гц (выше человеческого слухового максимума не требуется для музыки) |
| `n_fft` | 2048 | Размер окна STFT, ≈93 мс при sr=22050 |
| `hop_length` | 512 | Шаг STFT, ≈23 мс между фреймами |
| `n_mels` | 128 | Число мел-полос; 128 — стандарт для music classification |
| `fmin` | 30 Гц | Нижняя граница мел-фильтров |
| `fmax` | sr/2 = 11025 Гц | Верхняя граница (Найквистова частота) |

Логарифмическая компрессия применяется через `librosa.power_to_db(..., ref=np.max)` — нормализация к максимальному значению в треке, что даёт значения в диапазоне примерно [−80, 0] дБ.

### 3.2.2 Окновая нарезка (windowing)

Каждый трек разбивается на перекрывающиеся окна фиксированной длительности. Параметры:

- `window_seconds = 10.0` — длительность окна (10 секунд = 431 фрейм спектрограммы).
- `hop_seconds = 1.0` — шаг между окнами (1 секунда между началами).

Выбор `window_seconds = 10` обоснован двумя факторами. Во-первых, 10 секунд достаточно для типичного музыкального периода (один-два куплета или припев), что позволяет CNN модели «видеть» полный смысловой фрагмент. Во-вторых, AST-модель (см. §4.5) была предобучена на AudioSet с окнами 10 секунд, и сохранение этого размера позволяет напрямую использовать предобученные веса без интерполяции positional embeddings.

Шаг 1 секунда обеспечивает плотное покрытие аудио: за минуту получаем ~50 окон, что даёт достаточную плотность для пост-обработки через Viterbi.

### 3.2.3 Глобальная нормализация

После извлечения признаков по всему обучающему сплиту вычисляются глобальные статистики mean и std по всем мел-полосам:

```python
features_train = np.concatenate([np.load(f)["features"] for f in train_files])
mean = features_train.mean(axis=(0, 2), keepdims=True)  # (1, n_mels, 1)
std = features_train.std(axis=(0, 2), keepdims=True) + 1e-6
np.savez("stats.npz", mean=mean, std=std)
```

Эти статистики применяются ко всем трём сплитам (train/val/test) перед подачей в модель: `(feat - mean) / std`. Без нормализации модель медленно сходится и выдаёт смещённые предсказания на новых треках. **Критическое требование** для inference: тот же `stats.npz` должен использоваться при обработке пользовательских аудиозагрузок — иначе предсказания будут систематически неверными. В нашем пайплайне `musicml/infer.py:extract_features()` автоматически загружает `stats.npz` из стандартных путей.

## 3.3 Стратегия разбиения train/val/test

Каждый из трёх датасетов независимо разбивается в пропорции **70 / 15 / 15** (train / validation / test). Принципиальные решения:

1. **Разбиение на уровне треков, не окон.** Если бы мы перемешали окна и разделили на сплиты, окна одного трека попадали бы и в train, и в test, что давало бы ложно-завышенные метрики из-за корреляции между соседними окнами. Разбиение на уровне треков гарантирует, что модель не «видит» test-треки при обучении.

2. **Стратификация для GTZAN.** GTZAN строго сбалансирован (по 100 треков на жанр), стратификация выполняется автоматически при последовательном делении 70:15:15 = 70:15:15 треков на класс.

3. **Стратификация для DEAM невозможна.** Поскольку каждый DEAM-трек имеет покадровые непрерывные аннотации, разные фрагменты одного трека могут принадлежать разным классам arousal/valence. Стратификация на уровне треков по сводной метке трека была бы артефициальна. Используется случайное разбиение с фиксированным seed=42.

4. **Harmonix без стратификации по жанру.** Аннотации Harmonix не содержат явной жанровой информации. Разбиение случайное с тем же seed=42.

5. **Воспроизводимость.** Список треков в каждом сплите сохраняется в `splits.json` при подготовке датасета, что позволяет воспроизвести точные сплиты в любой момент.

## 3.4 Дисбаланс классов

Анализ распределения классов в train-сплитах выявил критический дисбаланс по сегментной задаче:

**Таблица 3.2. Распределение классов в train-сплитах**

| Задача | Класс | Доля окон | Inverse-frequency weight |
|---|---|---|---|
| **Segment** | Verse | ~35% | 0.71 |
|  | Chorus | ~25% | 1.00 |
|  | Bridge | ~12% | 2.08 |
|  | Intro | ~10% | 2.50 (capped) |
|  | Instrumental | ~10% | 2.50 (capped) |
|  | Outro | ~8% | 2.50 (capped) |
| **Arousal** | Low / Mid / High | ~33% / 34% / 33% | ≈1.00 каждый |
| **Valence** | Dark / Neutral / Bright | ~33% / 33% / 34% | ≈1.00 каждый |
| **Genre** | каждый из 10 | ~10% | ≈1.00 каждый |

Сегментная задача — единственная сильно несбалансированная: Verse и Chorus совокупно занимают ~60% окон, тогда как Outro — менее 10%. Без специальной обработки модель с высокой вероятностью научится предсказывать только Verse и Chorus, игнорируя редкие классы.

Для устранения дисбаланса применяются три механизма:

1. **Inverse-frequency class weights** — каждый класс получает вес, обратно пропорциональный его частоте, с верхним порогом `max_class_weight=2.5` (выбран эмпирически, чтобы избежать чрезмерного усиления редких классов; см. §4.6).

2. **Focal Loss** [34] — модификация cross-entropy с фокусом на сложные примеры через множитель $(1-p_t)^\gamma$ при $\gamma = 1.5$. Снижает вклад уверенных правильных предсказаний и усиливает сложные.

3. **Per-task loss weight** — суммарный мульти-задачный loss балансируется через множитель `segment: 1.5` (остальные задачи: 1.0), компенсируя относительно меньший вклад structurial-задачи в общую функцию потерь из-за её большей сложности.

Эксперимент с более агрессивными параметрами (`segment_weight=3.5`, `focal_gamma=2.5`, `max_class_weight=3.5`) показал противоположный эффект — модель переобучается на редкие классы и теряет качество на доминирующих (см. §5.5, неудачный эксперимент CNN v3).

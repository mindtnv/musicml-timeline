# AST под капотом — полный разбор для защиты

Читать линейно. В каждом блоке: **что на входе → что происходит → что на выходе → зачем это надо**.

Обозначения: `ℝ^{A×B}` — матрица A на B; все размерности проверяемы.

---

## 0. Базовый матан, без которого ничего не понятно

### 0.1 Вектор, матрица, тензор
- **Вектор** `x ∈ ℝ^n` — столбец из n чисел.
- **Матрица** `W ∈ ℝ^{m×n}` — таблица m×n.
- **Тензор** — обобщение: трёхмерный это `ℝ^{a×b×c}` (например, батч из b×c-матриц).

### 0.2 Линейное преобразование
`y = W·x + b`, где `W ∈ ℝ^{m×n}`, `x ∈ ℝ^n`, `b ∈ ℝ^m`, `y ∈ ℝ^m`.
В коде: `torch.nn.Linear(in_features=n, out_features=m)` — внутри хранится W и b, обучаются градиентным спуском.

### 0.3 Активации
- **ReLU(x) = max(0, x)** — "обнулить отрицательные".
- **GELU(x) ≈ x · Φ(x)** (Φ — нормальное CDF), гладкая версия ReLU. Трансформеры используют GELU.
- **Sigmoid(x) = 1/(1 + e^{-x})** — давит в [0,1].
- **Softmax(x)_i = e^{x_i} / Σ e^{x_j}** — превращает вектор логитов в распределение вероятностей (сумма = 1).

### 0.4 Cross-Entropy Loss
Если модель выдаёт вероятности `p = softmax(logits)`, а истинный класс — `y`, то
`L = -log(p_y)`
Минимизируя это, мы "затаскиваем" вероятность правильного класса к 1.

### 0.5 Gradient Descent
`θ ← θ - η · ∂L/∂θ`
Автоматически считается через backpropagation (autograd в PyTorch).

## 1. Вход: сырое аудио

**На входе**: аудиофайл (.mp3/.wav).

**Процесс**:
- Загружаем через `librosa.load(path, sr=22050)` → ресемплим до 22050 Гц.
- Результат: 1D массив float32 амплитуд в диапазоне [-1, 1].
- Для окна 10 секунд: `N = sr × duration = 22050 × 10 = 220500` сэмплов.

**На выходе**: `x ∈ ℝ^{220500}`.

**Зачем 22050, а не 44100?** Человек слышит до 20 кГц, по Найквисту хватает 40 кГц выборки. 22 кГц — компромисс: экономим в 2 раза память и вычисления, почти не теряя информации для не-вокальных задач.

**Зачем окно 10 с?** Баланс: короче — не видно структуры (Chorus не отличим от Verse); длиннее — не влезает в память AST и теряется временная точность для сегментации.

## 2. Лог-мел спектрограмма

**На входе**: `x ∈ ℝ^{220500}`.

**Процесс — 3 шага**:

### 2.1 Short-Time Fourier Transform (STFT)
Берём окно длиной `n_fft=1024` сэмплов, двигаем с шагом `hop_length=512`. В каждом окне считаем FFT:
`STFT[k, t] = Σ_{n=0}^{1023} x[t·512 + n] · e^{-2πi·kn/1024}`

Получаем комплексную матрицу `STFT ∈ ℂ^{513 × T}`, где `T = N/hop = 220500/512 ≈ 431` фреймов, 513 частотных бинов (n_fft/2 + 1).

Берём модуль: `|STFT|²` — **power spectrogram**.

### 2.2 Mel-фильтры
513 линейных частот → 128 мел-бинов. Мел-шкала:
`mel(f) = 2595 · log10(1 + f/700)`
Треугольные фильтры равномерно распределены по mel-шкале. Умножаем: `mel_spec = M · |STFT|²`, где `M ∈ ℝ^{128×513}`.

### 2.3 Логарифм
`log_mel = 10 · log10(mel_spec + ε)` — приводим к децибелам.

**На выходе**: `log_mel ∈ ℝ^{128×T}`, T ≈ 431 для 10-секундного окна.

**Зачем мел, а не raw?** Человек логарифмически чувствителен к частоте: 100→200 Гц и 1000→2000 Гц воспринимаются как один "шаг" по высоте. Мел-шкала это имитирует — низкие частоты детализированы сильнее.

**Зачем log?** Громкость тоже логарифмична (шкала дБ). Плюс стабилизирует обучение: без лога у громких звуков значения в 1000× больше тихих, градиенты взрываются.

## 3. Патч-эмбеддинг

**На входе**: спектрограмма `128 × T` (≈ картинка 128×431 в одном канале).

**Процесс — идея из Vision Transformer**:
1. Режем спектрограмму на **патчи 16×16** с шагом 10 (overlap, у AST).
2. Каждый патч = 16×16 = 256 чисел → вытягиваем в вектор ℝ^256.
3. Прогоняем через Linear: `patch_emb = W_patch · x_patch`, где `W_patch ∈ ℝ^{768×256}`.

**Количество патчей**: примерно `(128/16) × (T/10)` — для AudioSet-AST стандарт 8 частотных × ~48 временных = 384 патча на окно 10 с.

**На выходе**: `Z ∈ ℝ^{N×768}`, N ≈ 384 патчей (токенов), каждый размерности d=768.

**Зачем так?** Трансформер умеет работать только с последовательностями векторов. Надо превратить "картинку" спектрограммы в такую последовательность. Linear-проекция обучается находить осмысленное представление каждого патча.

---

## 4. CLS токен + позиционный эмбеддинг

**На входе**: `Z ∈ ℝ^{384×768}`.

### 4.1 CLS-токен
Добавляем в начало обучаемый вектор `cls ∈ ℝ^{768}`:
`Z' = [cls; z_1; z_2; ...; z_384] ∈ ℝ^{385×768}`

### 4.2 Позиционные эмбеддинги
У трансформера **нет** понятия порядка! Если перемешать токены — результат тот же. Чтобы ввести позицию:
`Z'' = Z' + E_pos`, где `E_pos ∈ ℝ^{385×768}` — обучаемые векторы позиций.

**На выходе**: `Z'' ∈ ℝ^{385×768}`.

**Зачем CLS?** Это "карман", в который трансформер через self-attention **стекает** итоговую информацию о всём окне. На выходе берём только его — одна векторная сводка 10 с аудио.

**Зачем pos emb?** Без неё модель не отличит "Intro → Verse → Chorus" от "Chorus → Verse → Intro".

---

## 5. Self-Attention — ядро трансформера (САМОЕ ВАЖНОЕ)

**На входе**: `X ∈ ℝ^{L×d}`, L=385, d=768.

### 5.1 Q, K, V — три проекции
```
Q = X · W_Q    (queries — "что я ищу")
K = X · W_K    (keys — "что я содержу")
V = X · W_V    (values — "что я отдам, если меня найдут")
```
Все `W_Q, W_K, W_V ∈ ℝ^{d×d_k}`, где в multi-head случае d_k = d/h = 64 (12 голов).

### 5.2 Матрица внимания
```
scores = Q · K^T        ∈ ℝ^{L×L}
scores = scores / √d_k  (для стабильности градиентов)
A = softmax(scores, dim=-1)   ∈ ℝ^{L×L}
```
`A[i, j]` = насколько токен i "смотрит" на токен j. Каждая строка суммируется в 1.

### 5.3 Агрегация
```
Out = A · V   ∈ ℝ^{L×d_k}
```
Каждый токен — взвешенная сумма значений всех остальных, где веса = attention.

### 5.4 Multi-Head
Делаем h=12 параллельных SA с разными W_Q, W_K, W_V, конкатенируем:
```
MHSA(X) = Concat(head_1, ..., head_12) · W_O
```
`W_O ∈ ℝ^{d×d}` — выходная проекция.

**Зачем несколько голов?** Каждая голова учит свой "паттерн внимания": одна следит за ритмическими соседями, другая — за гармоническими, третья — за вокальными патчами. Разнообразие.

**Интуиция SA для музыки**: патч, соответствующий припеву на 30-й секунде, через attention "подсвечивает" схожие припевные патчи по всей длительности окна. Модель понимает, что это **повтор**, а не случайный кусок.

## 6. FFN — полносвязный блок

**На входе**: `X ∈ ℝ^{L×d}`, d=768.

```
FFN(x) = W_2 · GELU(W_1 · x + b_1) + b_2
```
- `W_1 ∈ ℝ^{d × 4d}` = ℝ^{768×3072} — **расширение** в 4× раза.
- `W_2 ∈ ℝ^{4d × d}` = ℝ^{3072×768} — **сжатие** обратно.
- GELU между — нелинейность.

Применяется **независимо к каждому токену** (без attention).

**Зачем 4× расширение?** Создаёт "пространство для манипуляций": в большем пространстве модель может нелинейно комбинировать признаки. Это правило 4× — эмпирика из оригинальной статьи Vaswani et al.

**Зачем FFN вообще?** Self-attention — **линейная** операция (взвешенная сумма). Без FFN модель — один большой Linear. FFN вводит нелинейность и "думает" над каждым токеном отдельно.

---

## 7. Residual + LayerNorm

Каждый блок трансформера:
```
y = LayerNorm(x + MHSA(x))
z = LayerNorm(y + FFN(y))
```

**Residual (skip connection)**: `x + f(x)` — добавляем вход к выходу.
- **Зачем?** В глубоких сетях градиенты затухают. Skip-connection создаёт "прямой путь" для градиента. Без этого трансформеры в 12+ слоёв не обучаются.

**LayerNorm**: нормализует каждый токен по его d-размерности:
```
LN(x) = γ · (x - μ)/σ + β
```
μ и σ считаются по 768 признакам каждого токена, γ и β — обучаемые параметры.
- **Зачем?** Стабилизирует распределение активаций → быстрее и стабильнее обучение.

---

## 8. Стек из 12 блоков

Блок:
```
x → MHSA → add residual → LayerNorm → FFN → add residual → LayerNorm → выход
```

Стек: 12 таких блоков последовательно. Выход i-го = вход (i+1)-го.

В нашем AST:
- **Слои 1–8**: frozen — веса загружены из предобученного AudioSet-AST, `requires_grad = False`. Оптимизатор их не трогает.
- **Слои 9–12**: обучаемые, `requires_grad = True`, LR = 5×10⁻⁵ (в 20× меньше, чем для голов).

**Почему 8 и 4, а не 12 и 0 / 0 и 12?**
- Все 12 обучать с нуля → 87М параметров, 3544 трека — переобучимся и потеряем предобучение.
- Все 12 заморозить → модель не адаптируется под наши задачи (AudioSet — 527 классов звуков, не про музыкальную структуру).
- 8+4 — эмпирический компромисс: low-level слои (1–8) универсальны (тембр, ритм), high-level (9–12) задаче-специфичны — их и дообучаем.

## 9. Pooling: берём только CLS

**На входе**: `Z_final ∈ ℝ^{385×768}` — выход 12-го блока.

```
h = Z_final[0]   # CLS-токен
```

**На выходе**: `h ∈ ℝ^{768}` — одна векторная сводка всего окна 10 с.

**Зачем именно CLS?** Через 12 слоёв attention он "пылесосом" вобрал информацию со всех 384 патчей. Альтернатива — mean-pooling по всем токенам — тоже работает, но CLS обычно даёт чуть лучше, потому что он **специализируется** под эту роль (обучается быть сводкой).

## 10. Общий FC `768 → 256`

```
shared = Dropout(GELU(Linear_768→256(h)))
```

**На выходе**: `shared ∈ ℝ^{256}`.

**Зачем сжимать в 256?** Хватает для 4 задач, меньше параметров в головах, меньше шанс переобучения. Плюс "бутылочное горлышко" заставляет модель выучить компактное универсальное представление.

**Зачем общий для всех задач?** Hard parameter sharing в multi-task:
- Задачи скоррелированы (жанр определяет эмоции, эмоции — структуру).
- Общее ядро получает градиенты от всех 4 задач сразу → регуляризация.
- Экономия параметров: 4 × Linear(768→256) было бы в 3× больше.

## 11. 4 классификационные головы + 2 регрессионные

Каждая голова:
```
logits_k = Linear_256→K(shared)
probs_k  = softmax(logits_k)
```

| Голова | K | Классы |
|--------|---|--------|
| Сегмент | 6 | Intro, Verse, Chorus, Bridge, Instrumental, Outro |
| Возбуждение (arousal) | 3 | low, mid, high |
| Валентность (valence) | 3 | negative, neutral, positive |
| Жанр | 10 | blues, classical, country, disco, hiphop, jazz, metal, pop, reggae, rock |

Для регрессии:
```
â_reg = sigmoid(Linear_256→1(shared))   ∈ [0, 1]
v̂_reg = sigmoid(Linear_256→1(shared))   ∈ [0, 1]
```

### 11.1 Loss функции

**Для классификации**:
```
L_k = -log(probs_k[y_true])     # cross-entropy
```
с label smoothing=0.1 (истинный класс = 0.9 вместо 1.0, остальное = 0.1/(K-1)) — регуляризация.

**Для регрессии**:
```
L_reg = (â - y_a)²    # MSE
```

**Multi-task loss**:
```
L_total = 1.5 · L_seg + 1.0 · L_a + 1.0 · L_v + 1.0 · L_g + 0.5 · L_a_reg + 0.5 · L_v_reg
```
Веса λ_k подобраны эмпирически: сегменту +1.5, чтобы не проигрывал более лёгкой задаче жанра.

### 11.2 Weighted cross-entropy
Для сегментации классы несбалансированы (Verse/Chorus частые, Bridge редкий). Веса:
```
w_k = 1 / freq(k)          # inverse frequency
w_k = clip(w_k, max=2.5)   # cap to avoid extreme
```
Без этого модель предсказывала бы только Verse.

## 12. Постобработка: Витерби + позиционные приоры

Эта часть **не обучается**, применяется на инференсе.

**Задача**: модель выдаёт для каждой секунды t распределение по 6 сегментам `p_t ∈ [0,1]^6`. Если брать argmax в каждой секунде независимо — хаос: Chorus→Verse→Chorus→Bridge за 3 секунды.

### 12.1 Viterbi как HMM-decoding
Скрытая марковская модель:
- Состояния: 6 сегментов.
- Emission: `p_t[k]` — вероятность видеть наблюдение в состоянии k.
- Transition: `T[i, j]` — вероятность перейти из i в j.

DP (динамика):
```
δ_0[k] = log(π[k]) + log(p_0[k])              # начальные вероятности
δ_t[k] = max_j (δ_{t-1}[j] + log(T[j,k])) + log(p_t[k])
```
`ψ_t[k]` — argmax-аргумент, для бектрэкинга. В конце восстанавливаем оптимальную последовательность.

Transition matrix сконструирована вручную: `T[k, k] = 0.95` (остаться), `T[k, j≠k] = 0.05/5` (перейти) — штраф за частые смены.

### 12.2 Position priors
Intro встречается в начале, Outro — в конце. Добавляем лог-буст:
```
log(p_t[Intro])  += α · exp(-t/τ)       # α=2.0, τ=15с
log(p_t[Outro])  += α · exp(-(T-t)/τ)
```
Модель чаще ставит Intro на 5-й секунде, чем на 150-й.

### 12.3 Min duration
После Viterbi: слияние сегментов короче 6 с с соседом по большей emission-вероятности.

**Результат**: Boundary F1 с 0.31 → 0.45 (+14 pp, +45%).

## 13. Обучение — процесс

### 13.1 RoundRobin multi-task
Три датасета (DEAM, Harmonix, GTZAN) — каждый со своим набором лейблов:
- DEAM: arousal, valence.
- Harmonix: segment.
- GTZAN: genre.

**RoundRobin**: iteration 1 — батч из DEAM (loss = L_a + L_v), iteration 2 — батч из Harmonix (L_seg), iteration 3 — GTZAN (L_g), и по кругу. Общие слои получают градиенты от всех задач по очереди.

### 13.2 Optimizer & schedule
```python
optimizer = AdamW(
    [{'params': backbone, 'lr': 5e-5},    # trainable AST layers
     {'params': heads,    'lr': 1e-3}],   # classification heads
    weight_decay=0.01
)
scheduler = CosineAnnealingWarmRestarts(T_0=10, T_mult=2)
```
- **AdamW** = Adam + правильная L2-регуляризация.
- **Discriminative LR**: бэкбон дообучаем мягко (веса уже хорошие), головы с нуля — агрессивнее.
- **Warm restarts**: LR косинусно спадает за 10 эпох, потом прыгает обратно в max — помогает выбираться из локальных минимумов.

### 13.3 Batch
- `batch_size = 16` физический.
- `gradient_accumulation_steps = 4` — аккумулируем 4 мини-батча, делаем step → **эффективный батч 64**.
- `gradient_clipping(max_norm=1.0)` — обрезаем большие градиенты.

### 13.4 Аугментации
- **SpecAugment**: случайно маскируем полосы частот (`freq_mask=30`) и времени (`time_mask=60`) прямо на log-mel. Модель учится не полагаться на конкретные частоты/моменты.
- **Temporal jitter**: ±1 с случайный сдвиг окна для структурного датасета.
- **Mixup** (α=0.2): смешиваем два примера, `x_mix = λ·x_a + (1-λ)·x_b`, loss соответственно взвешенный.

### 13.5 Early stopping
Patience=15 эпох. Метрика: `val_loss` (сумма 4 задач на валидации). Сохраняем лучший чекпоинт.

## 14. Инференс — от файла до таймлайна

1. **Загрузка**: `librosa.load(path, sr=22050)`.
2. **Окна**: режем на 10-секундные окна с шагом 1 с (overlap 9 с).
3. **Feature**: log-mel для каждого окна → `(N_windows, 128, 431)`.
4. **Forward**: AST → CLS → FC → 4 softmax + 2 regression.
5. **Temporal smoothing**: для каждой секунды усредняем предсказания окон, которые её накрывают.
6. **Segment**: Viterbi + priors + min duration → чистый таймлайн.
7. **Emotion**: сглаживание скользящим средним (window=5 с).
8. **Genre**: per-track = argmax среднего по всему треку.
9. **Сводка JSON** → фронтенд.

## 15. Вопросы, которые задаст комиссия, и ответы

**Q: Почему AST, а не CNN?**
A: Для сегментации нужен **глобальный контекст** (что было в начале трека влияет на классификацию конца). CNN видит только локальное окно (рецептивное поле). Attention даёт связь "каждый-с-каждым". В нашем 2×2-эксперименте AST+Viterbi обошёл CNN baseline на сегменте на +7 pp.

**Q: Почему CLS-токен, а не среднее?**
A: CLS-вектор специально обучается быть сводкой (градиент идёт только через него в heads). Mean-pool даёт чуть хуже результат, потому что смешивает релевантные токены с шумом.

**Q: Сколько параметров и почему не больше?**
A: 87М всего, 14М обучаемых. Больше — переобучение на 3544 треках. Меньше — не хватает ёмкости для 4 задач. Эмпирически подобрано.

**Q: Почему self-attention квадратичный по L?**
A: Матрица `A ∈ ℝ^{L×L}`, для L=385 это 148K элементов — ок. Для длинных последовательностей (L>10K) используют Longformer / FlashAttention, нам не актуально.

**Q: Как считается Boundary F1?**
A: Предсказанная граница считается правильной, если есть истинная в пределах ±3 с. F1 = 2·P·R/(P+R), P и R — precision/recall границ. У нас 0.45 после Viterbi.

**Q: Почему multi-task, а не 4 отдельных модели?**
A: (1) экономия памяти (1 модель вместо 4 × 87М). (2) задачи коррелируют, shared representation регуляризует. (3) на практике получили +2 pp на arousal vs single-task в ablation.

**Q: Что с регрессией, если у DEAM нет per-window лейблов?**
A: DEAM даёт aggregate arousal/valence на весь трек. При обучении лейбл = одно число на трек, батч из DEAM содержит все его окна с одинаковым target → модель усредняет.

**Q: Что если аудио короче 10 с?**
A: Паддим нулями справа. SpecAugment в train случайно маскирует в т.ч. паддинг — модель учится игнорировать тишину.

**Q: Как выбрал λ=1.5 для сегмента?**
A: Без веса segment-loss доминировал шум (6 классов, дисбаланс 5:1:1:1:1:1), модель игнорировала задачу. Попробовали 1.0/1.5/2.0 — 1.5 дал лучший val_loss.

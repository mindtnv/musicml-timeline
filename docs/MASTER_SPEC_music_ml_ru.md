## 0) Коротко о цели
Нужно разработать **универсальный модуль анализа музыки**, который по входному аудиотреку строит временную разметку:

- **тип структурного сегмента**: `Calm`, `Build-up`, `Climax`, `Outro`
- **энергия (arousal)**: `Low`, `Mid`, `High`
- **настроение (valence)**: `Dark`, `Neutral`, `Bright`

Выход должен быть пригоден для последующей генерации параметров уровней ритм‑игр (плотность событий, цветовые переходы, сложность), но **в рамках прототипа** достаточно сформировать таймлайн (JSON) + визуализацию.

## 1) Объём работ (scope)
### Входит в проект
1. Извлечение аудиопризнаков (минимум: мел‑спектрограмма; опционально: chroma, MFCC, RMS).
2. Обучаемая модель ML (обязательно) — **CNN (сверточная сеть)**, предпочтительно мультизадачная:
   - голова A: `segment_class` (4 класса)
   - голова B: `arousal_class` (3 класса)
   - голова C: `valence_class` (3 класса)
3. Пост‑обработка предсказаний в сегменты (сглаживание, минимальная длина сегмента).
4. Экспериментальная оценка качества (метрики).
5. Инференс‑скрипт: аудио → JSON‑таймлайн (+ график).

### Не входит (можно оставить “на будущее”)
- Полная генерация pistolmix.json “как готовый уровень под ключ” (это следующий этап).
- Обучение больших аудио‑трансформеров и SOTA‑моделей (не нужно для магистерской НИР).

## 2) Определения и выходной формат
### 2.1 Типы сегментов (в терминах проекта)
- `Calm` — спокойные/разреженные участки, низкая интенсивность.
- `Build-up` — нарастание напряжения/плотности перед кульминацией.
- `Climax` — кульминация (припев/дроп/самый “плотный” фрагмент).
- `Outro` — финальная часть (затухание, завершение).

### 2.2 Эмоции
Используем модель arousal/valence (две оси):
- `arousal`: Low/Mid/High (интенсивность)
- `valence`: Dark/Neutral/Bright (условная “светлость” настроения)

### 2.3 Формат выхода (JSON)
Файл `timeline.json`:
```json
{
  "meta": {
    "audio_path": "path/to/song.wav",
    "sr": 22050,
    "hop_length": 512,
    "window_seconds": 8.0,
    "model": "cnn_multitask_v1",
    "created_at": "2026-02-25"
  },
  "segments": [
    {
      "start": 0.0,
      "end": 12.0,
      "segment_class": "Calm",
      "arousal_class": "Low",
      "valence_class": "Dark",
      "confidence": {
        "segment": 0.82,
        "arousal": 0.74,
        "valence": 0.61
      }
    }
  ],
  "frame_predictions": {
    "frame_hop_seconds": 1.0,
    "segment_probs": [],
    "arousal_probs": [],
    "valence_probs": []
  }
}
```

Примечания:
- `segments` — итоговые сглаженные участки.
- `frame_predictions` — опционально: вероятности по кадрам/окнам (нужно для графиков и отладки).

## 3) Входные данные и признаки (features)
### 3.1 Вход
- аудиофайл: WAV/MP3/FLAC (при обучении лучше WAV)
- приводим к:
  - mono
  - `sr = 22050` (или 44100 — но фиксируем один)

### 3.2 Основной признак: мел‑спектрограмма
Рекомендуемые параметры (можно менять, но фиксировать в конфиге):
- `n_fft = 2048`
- `hop_length = 512` (≈ 23 мс при 22050)
- `win_length = 2048`
- `n_mels = 128`
- `fmin = 30`, `fmax = sr/2`
- лог‑амплитуда (dB): `log_mel = power_to_db(mel)`

Почему это основной признак:
- компактно кодирует тембр/ритм/гармонию
- удобен для CNN (2D‑структура “частота×время”)

### 3.3 Дополнительные признаки (опционально)
**Вариант A: как дополнительные каналы входа CNN**
- `chroma` (12×T)
- `mfcc` (20×T)
- `rms` (1×T)

**Вариант B: как отдельный вектор (для “головы” MLP)**
- усреднение по окну: mean/std RMS, centroid, rolloff и т.п.

Для прототипа: начни с **только log‑mel**, потом добавь chroma/MFCC как абляцию.

## 4) Датасеты и стратегия обучения
Цель — минимизировать ручную разметку.

### 4.1 Датасет эмоций: DEAM
Используем для обучения `arousal` и `valence`.
- DEAM содержит разметку arousal/valence во времени (часто 1 Гц).
- Подготовка:
  1) режем трек на окна `window_seconds` (например 8s) со сдвигом `hop_seconds` (например 1s)
  2) для каждого окна берём среднее arousal/valence
  3) дискретизируем в классы:
     - arousal: Low/Mid/High
     - valence: Dark/Neutral/Bright

**Дискретизация (рекомендуется):**
- по квантилям train‑набора (33%/66%), чтобы классы были примерно сбалансированы.

### 4.2 Датасет структуры: SALAMI / Harmonix
Используем для обучения `segment_class`.

**Важно:** в исходной разметке могут быть метки intro/verse/chorus/bridge/outro и т.п.
Нужно сопоставить их нашим 4 классам.

**Пример маппинга (правило):**
- `chorus`, `drop` → `Climax`
- `bridge`, `pre-chorus`, `build`, `transition` → `Build-up`
- `intro`, `verse`, `break`, `interlude` → `Calm`
- `outro`, `ending` → `Outro`
- неизвестное → `Calm` (или пропуск, если метка нерелевантна)

**Подготовка примеров:**
- Для каждого аннотированного сегмента берём аудио‑фрагмент (или окна внутри сегмента) → метка `segment_class`.

### 4.3 Как обучать одну мультизадачную модель на разных датасетах
Реалистичная схема (без объединённой разметки):
- делаем **multi‑dataset training**:
  - batch из DEAM: считаем loss только для arousal/valence
  - batch из SALAMI/Harmonix: считаем loss только для segment_class
- общая “тушка” CNN общая, головы разные.
- итоговый loss: `loss = w_seg*loss_seg + w_ar*loss_ar + w_val*loss_val`, где отсутствующие лоссы = 0.

Это удобно для магистерской: честный ML, минимум ручной разметки.

## 5) Модель (минимальная, но качественная)
### 5.1 Архитектура CNN (v1)
Вход: `C × F × T` (C=1..N каналов, F=128, T зависит от окна)

Backbone:
- Conv2D(32, 3×3) + BN + ReLU + MaxPool
- Conv2D(64, 3×3) + BN + ReLU + MaxPool
- Conv2D(128, 3×3) + BN + ReLU + GlobalAvgPool

Heads:
- FC → softmax(4)  (segment_class)
- FC → softmax(3)  (arousal_class)
- FC → softmax(3)  (valence_class)

### 5.2 Обучение
- optimizer: AdamW
- lr: 1e-3 (потом scheduler)
- epochs: 20–60 (по ранней остановке)
- batch size: 16–64 (по VRAM)
- regularization: dropout 0.2–0.5
- mixed precision: да (если удобно)

---

## 6) Пост‑обработка в “сегменты”
Модель выдаёт предсказания по окнам/кадрам → нужно склеить в сегменты.

Минимальный алгоритм:
1) получаем последовательность предсказаний (класс + вероятность) с шагом `hop_seconds`
2) сглаживаем (median filter / majority vote) в окне 3–9 кадров
3) склеиваем соседние одинаковые классы
4) применяем правила:
   - минимальная длина сегмента (например 6–10 секунд)
   - если сегмент слишком короткий — объединить с соседом по максимальной вероятности
5) для каждого сегмента считаем confidence = средняя max‑prob по кадрам

## 10) Риски и как их закрыть
- **Разные датасеты, разная разметка** → multi‑dataset training + явное описание маппинга меток.
- **Недоступность аудио в SALAMI** → используем Harmonix/другие доступные источники либо собственный мини‑набор для сегментов; в отчёте честно описываем ограничения.
- **Мало данных под “Build-up”** → объединяем редкие метки, делаем балансировку классов, аугментации.
- **Субъективность эмоций** → используем дискретизацию по квантилям, оцениваем устойчивость и приводим примеры.
